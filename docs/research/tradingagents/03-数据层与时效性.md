# 数据层与数据时效性（point-in-time correctness）

本章只讨论 TradingAgents v0.5.0 的**数据获取层**：数据从哪里来、如何在 vendor 之间路由、用什么机制保证「在某个 as-of 日期做研究时只用当时可得的数据」。

事实来源为 `/tmp/TradingAgents`（commit `2d17df8`，v0.5.0）。结论以 `路径:行号` 标注；源码未明示处标注「未确认」。TradingAgents 默认市场是美股（Yahoo Finance / 美国 SEC / 美国 FRED），本章不涉及 A 股数据源，只在第 7 节讨论迁移差异。

---

## 1. 数据层整体架构

### 1.1 三层结构

```text
LLM 可见的 Tool（LangChain @tool，agents/utils/*_tools.py）
    │  唯一职责：注入 graph state 里的 trade_date，然后调用路由
    ▼
Router（dataflows/interface.py::route_to_vendor）
    │  唯一职责：按配置选 vendor 链、按错误类型降级、决定抛出还是产出 sentinel
    ▼
Vendor 实现（y_finance.py、alpha_vantage_*.py、sec_edgar.py、fred.py、polymarket.py …）
    │  唯一职责：拉数据、做本 vendor 的 point-in-time 过滤、渲染成文本
    ▼
外部 HTTP API
```

vendor 实现之间互不引用；`interface.py` 用 import 把各 vendor 的同名函数收拢成一张 dispatch 表（`interface.py:3-36`）。

### 1.2 `interface.py` 的实际公开面

需要先纠正一个误解：v0.5.0 的 `interface.py`（284 行）**不导出面向 LLM 的工具函数**，它导出路由机制的四个常量与三个函数。带 `@tool` 装饰器、暴露给模型的是 `tradingagents/agents/utils/*_tools.py`。对 Aegis 的类比意义：Eino 侧应对应「能力路由」与「工具注册」两层，而不是一个函数兼两职。

| 符号 | 签名 / 形态 | 行号 | 用途 |
|---|---|---|---|
| `TOOLS_CATEGORIES` | `dict[str, {"description": str, "tools": list[str]}]` | 41-83 | 工具 → 类别的静态归类表，6 个类别 |
| `VENDOR_LIST` | `list[str]` | 85-91 | 声明 5 个 vendor 名；**仓库内无消费者**，属遗留常量 |
| `OPTIONAL_CATEGORIES` | `set[str]` | 98 | `{"macro_data", "prediction_markets"}`，失败降级为 sentinel |
| `VENDOR_METHODS` | `dict[str, dict[str, callable]]` | 101-153 | 方法 → {vendor 名: 实现} 的 dispatch 表 |
| `get_category_for_method(method: str) -> str` | 函数 | 155-160 | 反查类别；未收录则 `raise ValueError` |
| `get_vendor(category: str, method: str = None) -> str` | 函数 | 162-175 | 取 vendor 配置，tool 级优先于 category 级 |
| `route_to_vendor(method: str, *args, **kwargs)` | 函数 | 177-284 | 唯一执行入口：选链、调用、降级、产出 sentinel 或抛错 |

六个类别（`interface.py:41-83`）为 `core_stock_apis`、`technical_indicators`、`fundamental_data`、`news_data`、`macro_data`、`prediction_markets`。类别是**配置与降级的粒度**，不是数据语义粒度：`fundamental_data` 一个类别里既有三家 vendor 都支持的财报，也有只一家支持的 `get_fundamentals`。

### 1.3 vendor 选择

```python
def get_vendor(category: str, method: str = None) -> str:
    config = get_config()
    if method:                                  # tool-level takes precedence
        tool_vendors = config.get("tool_vendors", {})
        if method in tool_vendors:
            return tool_vendors[method]
    return config.get("data_vendors", {}).get(category, "default")
```

配置项名称与默认值（`default_config.py:139-149`）：

```python
"data_vendors": {
    "core_stock_apis": "yfinance", "technical_indicators": "yfinance",
    "fundamental_data": "yfinance", "news_data": "yfinance",
    "macro_data": "fred",                # needs FRED_API_KEY
    "prediction_markets": "polymarket",  # keyless
},
"tool_vendors": {},   # 示例: "get_stock_data": "alpha_vantage"
```

配置是模块级单例：`set_config` 对 dict 值做一层浅合并、标量替换，`get_config` 返回 `deepcopy`（`config.py:16-37`）。意图是让 `{"data_vendors": {"core_stock_apis": "alpha_vantage"}}` 不破坏其余嵌套默认值；代价是**进程内全局可变状态**，测试须靠 `set_config` 复位（`tests/test_date_boundaries.py:44`）。

### 1.4 `route_to_vendor`：配置即降级链

**决策一：配置里的 vendor 列表就是完整降级链，不隐式兜底**（`interface.py:188-202`）：

```python
# The configured vendor list IS the chain: we do NOT silently fall back to
# vendors the user did not choose (#988/#289) — that returned data from an
# unexpected source and caused cross-vendor inconsistencies.
explicit = [v for v in primary_vendors if v and v != "default"]
if explicit:
    vendor_chain = [v for v in explicit if v in VENDOR_METHODS[method]]
    if not vendor_chain:
        raise ValueError(f"Configured vendor(s) {explicit} not available for '{method}'. …")
else:
    vendor_chain = all_available_vendors
```

配置里写了不支持的 vendor 会**立刻抛 `ValueError`**，而非静默跳过。代价是拼错名字会让链路启动即失败。`interface.py:208-209` 还预留了「同一 vendor 多实现」的列表形态分支（`vendor_impl[0] if isinstance(...)`），当前无任何条目使用。

**决策二：错误按类型决定降级语义，而非按 vendor**（`interface.py:207-234`）：

```python
for vendor in vendor_chain:
    try:
        return impl_func(*args, **kwargs)
    except VendorRateLimitError as e:      # throttled -> next vendor
        last_unavailable = e; continue
    except VendorNotConfiguredError as e:  # missing key -> vendor unavailable
        if first_error is None: first_error = e
        continue
    except NoMarketDataError as e:         # no data here, another may have it
        last_no_data = e; continue
    except Exception as e:
        # never swallow silently: a broken primary must be visible (#989)
        logger.warning("Vendor %r failed for %s: %s", vendor, method, e)
        if first_error is None: first_error = e
        continue
```

**决策三：链路尽头输出有语义的 sentinel 而非异常**（`interface.py:236-282`），三种终局互斥且优先级明确：

| 终局条件 | 输出 | 行号 |
|---|---|---|
| 任一 vendor 报 `NoMarketDataError` | `NO_DATA_AVAILABLE: No usable market data for '<sym>' … Do not estimate or fabricate values …` | 240-260 |
| 全部限流/不可达，且无 no-data | `DATA_UNAVAILABLE: no configured vendor could serve <method> right now (…)` | 268-273 |
| 其余真实错误 + 可选类别 | `DATA_UNAVAILABLE: optional <category> could not be retrieved (…)` | 275-281 |

其余真实错误且属于核心类别时 `raise first_error`（`interface.py:282`）。`NO_DATA_AVAILABLE` 优先于其他错误（`interface.py:236-247`），注释理由是「符号不可用」比「某 vendor 恰好出错」更接近本质；同时存在真实错误时只写日志。sentinel 是**字符串**，没有结构化字段，下游无法程序化区分「符号不存在」与「数据过期」——只能读 `detail` 文本。Aegis 的 `as_of` + `risk[]` 契约恰好可补这一层。

## 3. point-in-time correctness 机制

### 3.1 四道防线

```text
① 运行期钳制     工具边界强制 curr_date <= trade_date
                 （date_window.as_of / as_of_window + InjectedState("trade_date")）
② 请求期         把 as-of 传给 API（FRED realtime 钉 vintage；AV time_from/time_to）
③ 结果裁剪       按日期裁到 as-of（OHLCV <= curr_date；财报列；新闻 in_window；EDGAR filed <= curr_date）
④ 时效校验       裁剪后仍校验是否够新、是否可证明为缺失、字段有无历史 vintage
```

关键点：**裁剪（③）与时效校验（④）是两件事**。③ 保证不出现未来行；④ 保证不出现「旧的被当成新的」以及「没观测到被当成不存在」。

### 3.2 运行期钳制：`as_of` / `as_of_window`

防的是**模型传错日期**，不是供应商返回错数据（`date_window.py:69-79`）：

```python
def as_of(requested: str | None, trade_date: str) -> str | None:
    """The date a tool serves: the model's date, but never later than the run's.

    A model can omit the date or pass today's instead of the analysis date, which
    would walk past every point-in-time guard behind the tool.
    """
    if not trade_date:
        return requested
    parsed = _parse(requested)
    return requested if parsed is not None and parsed <= _parse(trade_date) else trade_date
```

三点语义：**取 min 而非拒绝**（模型给未来日期时静默钳到 `trade_date`，代价是模型不知被修正）；**空 `trade_date` 直通**（脱离 graph 直接调用时不钳制，是唯一的绕过路径）；**不可解析日期也回落 `trade_date`**（`_parse` 返回 `None` 时条件为假，`date_window.py:62-66,78-79`）。

`as_of_window` 处理整个区间（`date_window.py:82-92`）：当窗口完全落在 run 日期之后时，**保留窗口长度并整体平移**到以 `trade_date` 结尾，而不是返回空结果。这是一个明确权衡：宁可给语义相近的窗口，也不给必然为空的窗口。

`trade_date` 由 `Propagator` 注入 graph state（`graph/propagation.py:40`），进入图前校验格式且不得晚于今天（`graph/trading_graph.py:48-58`），工具侧统一用 `InjectedState("trade_date")` 读取。工具边界的分布：

| 工具 | 钳制方式 | 行号 |
|---|---|---|
| `get_stock_data`、`get_news` | `as_of_window(start, end, trade_date)` | `core_stock_tools.py:27`、`news_data_tools.py:27` |
| `get_indicators`、`get_verified_market_snapshot` | `as_of(curr_date, trade_date)` | `technical_indicators_tools.py:31`、`market_data_validation_tools.py:26` |
| `get_fundamentals` / 三张报表 | `as_of` | `fundamental_data_tools.py:25,45,65,85` |
| `get_global_news`、`get_macro_indicators` | `as_of` | `news_data_tools.py:51`、`macro_data_tools.py:39` |
| `get_insider_transactions`、`get_prediction_markets` | **参数里没有日期**，直接传 `trade_date or None` | `news_data_tools.py:66`、`prediction_markets_tools.py:33` |

最后一行是更强的设计：模型无从越权。CHANGELOG 0.5.0 记为「Dated tools take the run's date from graph state, so an omitted or later date cannot reach a vendor」（`CHANGELOG.md:24`）。

### 3.3 内容窗口：`in_window` 与 `coverage_gap`

新闻、Reddit、StockTwits 共享一条规则（`date_window.py:24-32`）：

```python
def in_window(pub_dt: datetime | None, start_dt: datetime, end_dt: datetime) -> bool:
    """Whether an item belongs in the half-open window ``[start, end + 1 day)``."""
    end = to_utc(end_dt)
    if pub_dt is not None:
        return to_utc(start_dt) <= to_utc(pub_dt) < end + timedelta(days=1)
    return end >= datetime.now(timezone.utc) - timedelta(days=1)
```

三条边界：**所有时间戳归一到 UTC**（`to_utc`，naive 值假定为 UTC，`date_window.py:19-21`；测试覆盖偏移换算与上界排他，`tests/test_social_lookahead.py:43-46`）；**上界是「end 次日零点」的开区间**，注释说明「an item stamped exactly then can't leak」（`date_window.py:6-8`）；**无时间戳条目在历史 run 中丢弃，仅当窗口触达当下才保留**——理由写在 docstring：「in a backtest we can't prove it isn't future」（`date_window.py:32`）。

时间戳解析质量决定这层是否生效。yfinance 新闻有两条路径（`yfinance_news.py:16-61`）：嵌套结构用 ISO `pubDate`；扁平结构用 epoch `providerPublishTime` 并**显式以 UTC 解析**，注释说明这是避免主机时区导致过滤偏移（`yfinance_news.py:49-54`，#1126）。该分支曾缺失，造成「flat articles … bypass the historical window and leak future news」（`yfinance_news.py:45-47`，#992/#1007）。

`coverage_gap` 处理**「未观测」与「不存在」的区分**（`date_window.py:35-59`）：

```python
def coverage_gap(dates, start_date, end_date, source, subject) -> str | None:
    now = datetime.now(timezone.utc)
    oldest = min((to_utc(d) for d in dates if d is not None), default=now)
    if datetime.strptime(end_date, "%Y-%m-%d").date() > now.date():
        reason = "the window extends past today"
    elif oldest.date() > datetime.strptime(start_date, "%Y-%m-%d").date():
        reason = f"it only serves recent items (coverage starts {oldest:%Y-%m-%d})"
    else:
        return None
    return f"<{source} unavailable for {start_date}..{end_date}: {reason}, so this is not an absence of {subject}>"
```

判定只有两条，输出是**三段式文案**（来源 + 原因 + 显式的「这不是 absence」）。Reddit 还把固定 7 天回溯起点计入覆盖边界：未拿满一页时 `now - 7d` 也进 `dates`（`reddit.py:57-65`），使「只覆盖最近一周」可被证明。Yahoo 全局新闻因多路模糊搜索不构成连续覆盖，传空 `dates`、只以当下为界（`yfinance_news.py:192-194`、`date_window.py:46-49`）。

```python
# Deliberately unguarded: TIME_SERIES_DAILY_ADJUSTED returns the full series
```

即：**当裁剪是唯一防线时，裁剪本身不允许容错降级**。这与 CHANGELOG 0.3.1 记录的泄漏互为镜像——那次的原因是「payload 是 JSON 字符串，dict-only 的守卫跳过了过滤」（`CHANGELOG.md:139-141`）。两次修复指向同一条经验：**类型守卫不能比数据形态更窄**。

```python
for fact in unit_values:

                                       - date.fromisoformat(fact["start"])).days <= high:

        latest[fact["end"]] = fact
```

四条隐含假设均有注释支撑：**同一期取「不晚于 as-of 的最后一次申报」**，修正案从申报日起生效（docstring 举 Apple 2008 年总资产由 39.6B 被 2010 年修正案改为 36.2B，`sec_edgar.py:6-12`）；**durational fact 需跨度匹配**，`_SPANS = {"quarterly": (60, 115), "annual": (300, 400)}`，否则同一 `end` 下的季度与年初至今会混淆（`sec_edgar.py:73-76`）；**标签按优先级取首个命中、绝不跨标签求和**（`sec_edgar.py:42-44,151-153`）；**不推导 Q4**（`sec_edgar.py:218-223`）。CHANGELOG 0.5.0 记为「a figure restated later still reads as first reported」（`CHANGELOG.md:17`）。

### 3.5 时效校验：`_assert_ohlcv_not_stale`

守护常量（`stockstats_utils.py:20-29`）：

```python
# A vendor's latest OHLCV row this many calendar days before the requested date
# is treated as stale. Generous enough to span long holiday weekends, tight
# enough to catch the year-old frames yfinance occasionally returns (#1021).
MAX_OHLCV_STALE_DAYS = 10
# How long a same-day cache that does not yet reach the requested day may be
# reused before it is refetched (#1150).
OHLCV_CACHE_TTL_SECONDS = 900
```

校验实现（`stockstats_utils.py:144-178`）：

```python
    requested = pd.to_datetime(curr_date, errors="coerce")
    if pd.isna(requested): return              # unparseable date -> no verdict
    dates = _coerce_ohlcv_dates(data)
    if dates.empty: return                     # empty frames are the caller's case
    stale_days = (requested.normalize() - dates.max().normalize()).days
    if stale_days > max_stale_days:
        raise NoMarketDataError(symbol, canonical,
            f"latest row is …, {stale_days} days before the requested … (stale) — refusing to use it")
```

要点：**只惩罚「太旧」，不惩罚「太新」**——`stale_days` 为负时不触发，因为上游裁剪应保证不出现未来行。这意味着**若某条调用路径漏了裁剪，本函数不会发现**。**空帧不归它管**（`data.empty` 直接 return，`stockstats_utils.py:156-159`）。**10 个自然日**是刻意的宽松值：跨长假，同时抓住「返回一年前帧」的故障（#1021）；代价是停牌、退市边缘标的可能被误判为可用。调用点两处：`load_ohlcv`（`stockstats_utils.py:288`）与 `get_YFin_data_online`（`y_finance.py:59`）。

### 3.6 无历史 vintage 的字段：`withhold_live_profile`

有一类字段根本无法做 PIT：供应商只给「今天」的值。做法是**整体拒绝并解释**，而非给带警告的近似值（`date_window.py:95-121`）：

```python
def withhold_live_profile(curr_date: str | None, label: str) -> str | None:
    """Notice to serve instead of a live-only company profile, or None to serve it.

    Vendor "company overview" endpoints (yfinance ``Ticker.info``, Alpha Vantage
    ``OVERVIEW``) carry no historical vintage … so serving one into a run dated in
    the past leaks post-decision information (#1300). Every fundamentals vendor
    withholds on this rule, so switching between them cannot reintroduce the leak.
    """
    if not curr_date: return None
    if curr_date >= get_current_date(): return None
    return "# Company fundamentals are withheld for this date. …"
```

覆盖面是设计重点：yfinance（`y_finance.py:293-299`）与 Alpha Vantage（`alpha_vantage_fundamentals.py:47-49`）调用**同一个函数**，理由即 docstring 里的「switching between them cannot reintroduce the leak」。守卫发生在**发请求之前**（`y_finance.py:295-296` 注释：the response would only be discarded），既省配额也避免泄漏。

同一思路的另两例：**Polymarket** 对 `curr_date < today` 直接 withhold（`polymarket.py:86-91`）；**FRED** 用 `pit = min(curr_date, _fred_today())` 把 PIT 参数对齐供应商时钟（`fred.py:192`），因为 FRED 的 realtime 时钟走美中时间（`FRED_TZ = pytz.timezone("America/Chicago")`，`fred.py:28`），run 当日可能已比芝加哥早一天，未来日期会 400 从而静默丢掉整个宏观测（`fred.py:184-191`）。

### 3.7 `market_data_validator.py` 的定位（需要澄清）

模块名容易让人以为是「未来数据检测器」，实际不是。docstring 写明目标是**对抗 LLM 编造精确数字**（`market_data_validator.py:1-9`），产出「latest OHLCV row on or before the analysis date + 常用指标 + 近期收盘」的 ground truth 快照。它的 PIT 相关性只有两点（`market_data_validator.py:28-47`）：

```python
    # ``load_ohlcv`` already … filters out look-ahead rows, but we re-apply the
    # cutoff defensively — this is a verification path, so it must not trust its
    # input to be pre-filtered.
    data = load_ohlcv(symbol, curr_date, fill_gaps=False)
    df = df[df["Date"] <= pd.to_datetime(curr_date)].sort_values("Date")
```

一是**复核路径重新应用裁剪**；二是**`fill_gaps=False`**——因为快照数字会被当作精确价格引用，而填充过的格子「会把上一交易日的价格放在本交易日的日期下」（`market_data_validator.py:35-37`）。这暴露了 `load_ohlcv` 默认 `fill_gaps=True`（`stockstats_utils.py:196`）的已知副作用。固定指标集 `DEFAULT_SNAPSHOT_INDICATORS` 含 11 项，单指标失败只降级为 `N/A (ExcName)`（`market_data_validator.py:21-25,79-84`）；末尾附对抗性指令：冲突时「flag the discrepancy rather than inventing a reconciled number」（`market_data_validator.py:116-124`）。

### 3.9 已验证的防护缺口

1. **`get_YFin_data_online` 没有显式的日期上界裁剪**：它靠 `end_inclusive = end_dt + 1 day` 与 yfinance「end 排他」的约定保证闭端（`y_finance.py:40-44`），随后只做 `_assert_ohlcv_not_stale`（`y_finance.py:59`），而后者对「晚于请求日」的行不作处理（`stockstats_utils.py:171-172`）；对比 `load_ohlcv` 有显式 `<= curr_date_dt` 过滤（`stockstats_utils.py:263`）。**供应商若返回超出请求区间的行，工具路径不拦截，只有指标路径会。**
2. **`_fill_price_gaps` 使用 `ffill().bfill()`**（`stockstats_utils.py:117-124`，关键行 123）：`ffill` 把过去值放到后面的日期（upstream 已承认，`stockstats_utils.py:281-284`、`market_data_validator.py:35-37`），`bfill` 方向相反，把**后面的值回填到前面空缺的格子**。填充发生在裁剪之后，泄漏范围限于窗口内部，但对被填充行仍是前视。upstream 注释只讨论了 `ffill` 方向；**该缺口未被测试覆盖（未确认是否为有意的可接受权衡）**。
3. **yfinance 财报与内部人交易的 vintage 弱于 EDGAR**：分别按报告期（`y_finance.py:483-486`）与交易日（`y_finance.py:471-475`）裁剪并附文案警告，注释自述「a run dated in that gap can be served figures that were not yet public」——**明知不严格，用文案声明代替机制**。
4. **无交易日历**：`look_back_days` 全程按自然日（`y_finance.py:168,188`、`fred.py:182`），非交易日以字符串 `"N/A: Not a trading day (weekend or holiday)"` 输出（`stockstats_utils.py:330`），`MAX_OHLCV_STALE_DAYS = 10` 也是为容纳长假而放宽。**整个数据层没有任何 exchange calendar 依赖。**

## 4. 缓存与限流

### 4.1 只有两处本地缓存

| 缓存 | 路径与格式 | 键 | 命中策略 | 失效 |
|---|---|---|---|---|
| OHLCV | `{data_cache_dir}/{safe_symbol}-YFin-data.csv`（`stockstats_utils.py:225-229`） | 归一化 symbol | 文件存在 + 非空 + 含 `Close` 列 + `_cache_is_fresh` | 见下 |
| SEC EDGAR | `{data_cache_dir}/sec_edgar/{name}`，JSON，原子写 `.tmp` + `os.replace`（`sec_edgar.py:124-127`） | CIK / `company_tickers.json` | mtime 距今 < `_CACHE_TTL_SECONDS = 24*3600`（`sec_edgar.py:40,117`） | 纯时间 TTL |

其余 vendor（Alpha Vantage、FRED、Polymarket、Reddit、StockTwits）**无本地缓存**。

OHLCV 的命中条件是两段逻辑（`stockstats_utils.py:181-193`）：

```python
def _cache_is_fresh(data_file, curr_date_dt, now) -> bool:
    """… A current-day request also refetches once the file is older than the TTL:
    Yahoo publishes a partial daily candle during market hours, whose ``Close`` is
    not the closing price, and row inspection cannot tell it from a final one (#1150)."""
    written = pd.Timestamp.fromtimestamp(os.path.getmtime(data_file))
    if written.date() != now.date():
        return False
    return curr_date_dt.date() < now.date() or (now - written).total_seconds() <= OHLCV_CACHE_TTL_SECONDS
```

这解决的是**盘中数据完整性**问题而非性能问题：Yahoo 盘中会返回当天未收盘的日线，其 `Close` 不是收盘价，而**看行内容无法区分它与最终值**。因此缓存只在写入当天有效；请求历史日期时当天缓存即足够；请求当天时超过 900s 就重拉。

两条附带纪律：**空结果不落盘**——写入前检查 `downloaded.empty or "Close" not in downloaded.columns` 并抛错（`stockstats_utils.py:254-257`），读取时同样检查，使一次失败的下载不会永久毒化该 symbol（`stockstats_utils.py:231-242`）；**路径安全**——symbol 经 `normalize_symbol` 后再过 `safe_ticker_component`（`stockstats_utils.py:210-211`），后者用白名单正则 `^[A-Za-z0-9._\-\^=+]+$` 加长度与「全点」检查，理由是 ticker 可能来自 prompt 注入并被拼进 `os.path.join`（`utils.py:14-39`）。

### 4.2 重试与退避

| vendor | 策略 | 行号 |
|---|---|---|
| yfinance | 仅对 `YFRateLimitError` 重试，指数退避 `base_delay * 2**attempt`，默认 3 次（2/4/8s），其他异常直接抛出 | `stockstats_utils.py:43-59` |
| Reddit | 仅对 429 重试一次；有 `Retry-After` 用其值（上限 60s），无则 60s ± 20% 抖动 | `reddit.py:129-132,193-203` |
| Alpha Vantage | **无重试**，限流转 `AlphaVantageRateLimitError` 交给路由 | `alpha_vantage_common.py:109-117` |
| SEC EDGAR | **无重试**，任何请求失败即 `VendorRateLimitError` | `sec_edgar.py:100-112` |
| FRED / Polymarket | 无重试 | — |

`yf_retry` 包裹的是**单次 API 调用闭包**（如 `yf_retry(lambda: ticker_obj.info)`，`y_finance.py:303`），重试不会重复已完成的工作。Reddit 的抖动注释说明动因：多个分析共享出口 IP 时会「retry in lockstep and re-collide on the limit」（`reddit.py:124-125`）。

### 4.3 缓存是否引入陈旧数据

会，但每个场景都被显式界定：

1. **当日 CSV 的盘中 bar**：用 900s TTL 把暴露窗口限制在 15 分钟内，而非试图识别 bar 是否终值。
2. **跨日复用**：被 `written.date() != now.date()` 排除，不会出现「昨天的下载服务今天的请求」。
3. **SEC EDGAR 的 24h TTL**：**有意**接受陈旧，理由是「A filing history only changes when something new is filed」（`sec_edgar.py:38-40`）。由于该路径本身按 `filed <= curr_date` 过滤，延迟只会让数据**更保守**（少看到，不会多看到），方向上是 PIT 安全的。
4. **缓存与 PIT 的分工**：OHLCV 缓存保存「最近 5 年到今天」的全量下载（`stockstats_utils.py:216-223`），裁剪发生在**读取之后**（`stockstats_utils.py:262-263`）。同一文件可服务任意历史 as-of 而不泄漏未来行——**缓存层不参与 PIT，裁剪层才是唯一权威**。这也是可移植的设计：缓存按「数据源快照」存、不按「as-of 视图」存，避免为每个日期生成文件（CHANGELOG 0.5.0「One OHLCV cache file per symbol. (#1330)」，`CHANGELOG.md:55`）。

## 5. 技术指标计算

### 5.1 计算库与流程

指标全部委托 `stockstats.wrap()`（`stockstats_utils.py:8`），不自己实现公式：

```text
load_ohlcv(symbol, curr_date)   ← 已裁剪到 <= curr_date，已做 stale 校验
    ↓ wrap(data)                 ← 列名转小写，按需惰性计算
    ↓ df[indicator]              ← 访问即触发计算
    ↓ 取目标日期那一行 / 全量导出
```

惰性求值是理解这段代码的关键：`df[indicator]` 看似无副作用，实为触发点。三处都带解释性写法（`market_data_validator.py:81`、`y_finance.py:236`、`stockstats_utils.py:323`）。

### 5.2 指标清单

**（A）yfinance 路径的本地窗口指标**（`_get_stock_stats_bulk`，`y_finance.py:219-250`）：一次性对全量裁剪后数据计算，按日期字符串导出为 `dict[date_str, value]`，再在 `[before, curr_date]` 内逐自然日取值。13 个指标，每个都带面向 LLM 的用法说明（`best_ind_params`，`y_finance.py:88-159`）：

| 指标名 | 说明 | 分类 |
|---|---|---|
| `close_50_sma` / `close_200_sma` / `close_10_ema` | 50 SMA / 200 SMA / 10 EMA | 趋势 |
| `macd` / `macds` / `macdh` | MACD 线 / 信号线 / 柱 | 动量 |
| `rsi` | 相对强弱指标（70/30 阈值） | 动量 |
| `boll` / `boll_ub` / `boll_lb` | 布林中轨 / 上轨 / 下轨 | 波动 |
| `atr` | 平均真实波幅 | 波动 |
| `vwma` | 成交量加权移动平均 | 量能 |
| `mfi` | 资金流量指标（>80 / <20） | 量能 |

指标名不在表中直接 `raise ValueError` 并附完整可选列表（`y_finance.py:161-164`）——这是**调用方参数错误**，与「vendor 无数据」严格区分。

**（B）Alpha Vantage 路径的远端指标**（`alpha_vantage_indicator.py:37-50`）：同一套指标名，由供应商端点计算，12 项映射到 6 个 API function（`SMA`/`EMA`/`MACD`/`RSI`/`BBANDS`/`ATR`）加 CSV 列名映射（`alpha_vantage_indicator.py:162-167`）。两处细节：该列表**没有 `mfi`**，而 yfinance 路径有（`y_finance.py:154-158`），请求 `mfi` 会落到 `else` 分支抛 `NoMarketDataError` 让路由换 vendor（`alpha_vantage_indicator.py:141-147`）——这是**能力差异**而非错误，`NoMarketDataError` 被刻意用于「本 vendor 不服务」；`series_type` 会被指标硬性覆盖，例如 RSI 强制 `close`（`alpha_vantage_indicator.py:82-83`）。

**（C）快照指标集**：`close_10_ema`、`close_50_sma`、`close_200_sma`、`rsi`、`boll`、`boll_ub`、`boll_lb`、`macd`、`macds`、`macdh`、`atr`，共 11 项，为「每次 run 形态一致」而固定（`market_data_validator.py:21-25`）。

### 5.3 窗口对齐与未来数据

避免未来数据靠的是**顺序**，不是指标内部的窗口约束：

1. `load_ohlcv` 先按 `curr_date` 裁剪（`stockstats_utils.py:262-263`），**然后**才 `wrap()` 计算（`stockstats_utils.py:319`、`y_finance.py:231-232`）。任何滚动窗口都不可能触及 `curr_date` 之后的行。这就是「窗口对齐」的全部机制——**没有额外的 shift / 对齐代码**。
2. 输出时对目标日期精确匹配，未命中则返回 `"N/A: Not a trading day (weekend or holiday)"`（`stockstats_utils.py:324-330`）。
3. 区间输出的日期粒度是**自然日**：从 `curr_date` 逐日回退 `look_back_days` 天（`y_finance.py:166-188`），不在结果里的日期输出占位串（`y_finance.py:185`）。因此输出表格里**自然日与交易日混排**，靠字符串区分。对 A 股的启示：需要交易日历，否则「周末 / 节假日 / 停牌 / 数据未更新」四者无法区分。
4. 批量计算失败时回落逐日计算，且**先重抛 `VendorError` 再兜底**（`y_finance.py:195-196`），保证「符号不存在」不被降级路径掩盖。逐日路径的异常转成 `NoMarketDataError`，注释说明原因：空字符串在表格里渲染成 `2026-05-08: `，看起来像「那天没有值」，实际是「读取失败」（`y_finance.py:272-278`）。

## 6. 错误处理契约

### 6.1 类型定义

`errors.py` 全文 55 行，核心原则是「**错误类型的数量等于路由的不同反应数**」（`errors.py:1-16`）：

```python
class VendorError(Exception):
    """Base for any condition where a vendor could not return usable data."""

class NoMarketDataError(VendorError):
    """A vendor returned no usable rows for a symbol (empty result or stale data)."""
    def __init__(self, symbol: str, canonical: str | None = None, detail: str = ""):
        self.symbol = symbol
        self.canonical = canonical or symbol
        self.detail = detail
        msg = f"No market data for {symbol!r}"
        if canonical and canonical != symbol:
            msg += f" (queried as {canonical!r})"
        if detail:
            msg += f": {detail}"
        super().__init__(msg)

class VendorRateLimitError(VendorError):
    """A vendor throttled the request; the router skips to the next vendor."""

class VendorNotConfiguredError(VendorError, ValueError):
    """A vendor was selected but its API key/configuration is missing.

    Also a ``ValueError`` so existing callers that catch ``ValueError`` keep working.
    """
```

关键说明（`errors.py:13-15`）：

> The number of types is the number of distinct router reactions, not the number of human-describable causes: empty and stale data get identical handling, so they share `NoMarketDataError` and differ only in the free-text `detail`.

即「空结果」与「数据过期」**共用一个类型**，靠 `detail` 区分文本——两者的路由动作完全一致（换 vendor → 最终 `NO_DATA_AVAILABLE`）。`NoMarketDataError` 携带 `symbol`（请求符号）、`canonical`（实际查询的归一化符号）、`detail`（自由文本原因），`interface.py:248-254` 把 `detail` 原样带进面向 Agent 的说明，因此「latest row is 2025-06-11 … (stale)」这类信息会一直传下去，而不是被压成通用文案（注释明确说明这是意图，`interface.py:251-254`）。

### 6.2 vendor 特有子类

| 子类 | 继承 | 行号 | 触发 |
|---|---|---|---|
| `AlphaVantageNotConfiguredError` | `VendorNotConfiguredError` | `alpha_vantage_common.py:18-25` | key 缺失，或响应通知含 "api key" |
| `AlphaVantageRateLimitError` | `VendorRateLimitError` | `alpha_vantage_common.py:63-65` | 通知含 `rate limit` / `requests per day` / `call frequency` / `premium` |
| `FredNotConfiguredError` | `VendorNotConfiguredError` | `fred.py:82-88` | `FRED_API_KEY` 缺失 |

`alpha_vantage_common.py:105-117` 的分类顺序解决了一个真实歧义：

```python
# Alpha Vantage reports problems via "Information" / "Note". Classify so a
# genuine rate limit and an invalid/missing key aren't conflated (#991):
# rate-limit phrasing is checked first because those notices also mention "API key".
notice = response_json.get("Information") or response_json.get("Note")
if notice:
    low = notice.lower()
    if any(m in low for m in ("rate limit", "requests per day", "call frequency", "premium")):
        raise AlphaVantageRateLimitError(f"Alpha Vantage rate limit exceeded: {notice}")
    if "api key" in low or "apikey" in low:
        raise AlphaVantageNotConfiguredError(f"Alpha Vantage API key invalid or missing: {notice}")
```

「限流文案里也含 API key」使判定必须有序；顺序反了会把限流误报为配置错误。此外 Alpha Vantage 的错误体**不带 HTTP 错误码**（200 + `Information`），是把「HTTP 状态即错误」假设推翻的典型例子。

### 6.3 调用方如何区分失败

| 失败类别 | 类型 | 路由反应 | 最终呈现 |
|---|---|---|---|
| 无数据（含过期） | `NoMarketDataError` | 记 `last_no_data`，继续 | `NO_DATA_AVAILABLE: …` + `detail` |
| 限流 / 不可达 | `VendorRateLimitError` | 记 `last_unavailable`，继续 | 无 no-data 时 `DATA_UNAVAILABLE: …` |
| 权限 / 未配置 | `VendorNotConfiguredError`（也是 `ValueError`） | 记 `first_error`，继续 | 核心类别 `raise`；可选类别 `DATA_UNAVAILABLE: optional …` |
| 参数错误 | 裸 `ValueError` / `NoMarketDataError` | 视情况 | 指标名不合法 → `ValueError`（`y_finance.py:161-164`）；FRED 别名不合法 → 直接返回指导文案（`fred.py:196-201`） |
| 其他未分类异常 | `Exception` | 记 `first_error`，继续 | 核心类别 `raise`；可选类别降级为 sentinel |

两点细节：`VendorNotConfiguredError` 同时继承 `ValueError`（`errors.py:50`）是为了兼容既有 `except ValueError` 调用点，注释写明这一意图——这是「新错误类型不破坏既有捕获」的迁移技巧。**参数错误被区别对待**：指标名不合法时抛 `ValueError` 并被工具层捕获成文本返回（`technical_indicators_tools.py:37-38`），而 FRED 的非法别名**不抛错**，直接返回带示例的指导（`fred.py:196-201`）；理由是后者的调用者是 LLM，返回可执行提示比抛异常更有用。

`utils.get_scrubbed`（`utils.py:46-64`）是错误契约之外的安全约束：以查询参数认证的 vendor 会把 key 放进 URL，而 `requests` 异常文本含完整 URL，因此把 key 替换成 `***` 且**不链式保留原异常**：

```python
except requests.RequestException as exc:
    error = type(exc)(str(exc).replace(secret, "***")) if secret else exc
raise error
```

## 7. 对 Aegis 的可移植结论

Aegis 的对应层是 `docs/02-数据能力层.md` 的 Capability / Binding + 数据契约，以及 `docs/06-时间语义与输出契约.md` 的 `as_of` 语义。

### 7.1 可直接移植的机制

**(1) `as_of` 钳制放在能力边界，而非各 Provider 内部。** TradingAgents 把「模型传的日期不得超过 run 日期」实现在工具包装层（`core_stock_tools.py:27` 等），Provider 完全不感知。Aegis 已有 `as_of` 的语义定义（`docs/06-时间语义与输出契约.md:9-17`）和结构校验（`internal/agent/market/validator.go:13-15`），但缺少**运行期钳制**。建议在 Capability Resolver 的 `Invoke` 入口统一做 `min(input.AsOf, runContext.TradeDate)`，并实现窗口版本（对应 `as_of_window` 的「保留长度整体平移」语义，`date_window.py:82-92`）。注意 Aegis 用 `YYYYMMDD`、TradingAgents 用 `YYYY-MM-DD`，转换应集中在 Resolver 一处。`as_of` 缺失属结构非法（`validator.go`）——Aegis 这一点已比 TradingAgents 严格（后者空 `trade_date` 直接放行，`date_window.py:76-77`），不要退化。

**(2) 错误类型数量 = 路由反应数量。** `errors.py` 的三分法（无数据 / 限流 / 未配置）恰好对应 `docs/README.md` 第 8 条「降级判定不只看报错」。可映射为 Go sentinel error：`ErrNoData`（换 Binding，耗尽后写 `risk[]`）、`ErrRateLimited`（换 Binding）、`ErrNotConfigured`（换 Binding，核心能力最终报错）。关键是**让 `errors.Is` 成为降级判定的唯一依据**，Provider 内部不做降级决策——TradingAgents 用 `except` 子句承担这个角色（`interface.py:213-234`），Go 里就是 Resolver 中的 `errors.Is` 分支。

**(3) 「配置即降级链、不静默兜底」原则。** `interface.py:188-202` 的三条规则可直接照搬：配置列出的 Binding 即完整候选集、顺序即优先级；配置了但该能力不支持某 Binding → **启动期报错**（不是运行期静默跳过）；未配置才用全部可用 Binding。Aegis 的 `CapabilityBinding.Priority`（`docs/02-数据能力层.md:236-241`）表达力更强，但「配置错误必须在启动期暴露」这一点要显式实现，否则会退化成静默兜底。

**(4) 「未观测 ≠ 不存在」的显式建模。** `coverage_gap`（`date_window.py:35-59`）的三段式结构应成为 Aegis 数据契约里的**字段**而非文案：

```go
type Coverage struct {
    Observed bool   `json:"observed"`  // 数据源是否覆盖了请求窗口
    Reason   string `json:"reason,omitempty"`
}
```

TradingAgents 只能用文案表达，是因为它的输出契约是文本；Aegis 有结构化契约（`internal/tool/market/market.go:15-20`），应把它变成字段。这直接对应 A 股高频问题：Tushare 等接口在停牌、退市、新上市标的上返回空数组，「今天没有成交」与「这个代码不存在」必须能区分。

**(5) 供应商时钟与本地时钟不一致的钉住问题。** `fred.py:184-193` 的 `pit = min(curr_date, _fred_today())` 是易复现的教训。Aegis 对接 A 股数据源同样会遇到：本地 `time.Now()` 是 `2026-09-24 01:00 +08:00`，而交易所的「今天」是 `2026-09-23`。建议在 Capability 输入契约中区分 `RequestedAsOf` 与 `EffectiveAsOf`，由 Binding 声明它认可的时区/日历。

**(6) 「裁剪是唯一防线时不允容错」的纪律。** `alpha_vantage_common.py:138-142` 可直接落地为编码约束：**若某次解析是阻止未来数据进入系统的最外层保证，该解析失败必须返回 error，不能返回零值 + nil**。这条在 Go 里尤其重要，因为零值语义容易让「解析失败」静默变成「字段为空」。

**(7) 缓存按「数据源快照」存，裁剪在读取之后。** `stockstats_utils.py:262-263` 加 CHANGELOG #1330 的组合模式（一个 symbol 一个文件、存全量、PIT 靠读取后裁剪）可直接沿用。Aegis 若引入本地行情缓存，不应按 `(symbol, as_of)` 建键——那会导致文件爆炸且难以失效。同时沿用「空结果不落盘 + 已落盘空缓存视为 miss」（`stockstats_utils.py:231-242,254-257`）。

**(8) 当日未收盘 bar 的不可判定性。** `_cache_is_fresh` 的注释（`stockstats_utils.py:184-189`）直接对应 A 股：盘中拿到的日线 `Close` 不是收盘价，且**无法通过检查行内容区分**，因此不能用「字段非空 + 价格合理」当完整性判据。`docs/06-时间语义与输出契约.md:28-29` 已规定「当前交易日数据尚未完整时使用最近一个数据完整的交易日」；可移植的具体做法是给 Capability 输入加 `RequireFinalBar bool`，由 Binding 依据交易时段自主判定，而不是让上层猜测。

**(9) 路径安全与密钥脱敏。** `utils.py:14-39` 的 `safe_ticker_component` 针对「ticker 可能来自 prompt 注入并被拼进文件路径」，Aegis 的 symbol 同样来自 LLM 工具调用参数并可能进入缓存路径，值得原样移植（Go 侧一个 `regexp` + 长度 + 全点检查）。`utils.py:46-64` 的脱敏模式在 Go 里对应：包装 `http.Client.Do`，在构造 error 前把 API key 从 URL 替换掉，并**不用 `%w` 链式保留原始 `*url.Error`**（其 `Error()` 含完整 URL）。Aegis 已记录 `configs/mcp.json` 里 Tushare token 明文写在 URL 查询串的问题，这条直接相关。

### 7.2 需要按 A 股语义改造的部分

**(1) 交易日历是硬需求，TradingAgents 完全没有。** 全库无 calendar 依赖，`look_back_days` 一律按自然日（`y_finance.py:168`、`fred.py:182`），非交易日只输出占位串（`stockstats_utils.py:330`），`MAX_OHLCV_STALE_DAYS = 10` 也是为容纳长假才放宽。A 股需额外区分周末、法定节假日、**停牌**、**当日数据未更新**。Aegis 应在能力层引入 exchange calendar，把「窗口」定义为交易日而非自然日，并让 `stale` 判定基于「距上一个交易日的距离」。这不是可借鉴项，而是 TradingAgents 的已知短板。

**(2) PIT 的时间基准应取「披露日」而非「报告期」。** TradingAgents 的三个层次构成参照表：EDGAR 用 `filed`（最强，`sec_edgar.py:154-172`）；yfinance/Alpha Vantage 用 `period end` 加文案声明（最弱，`y_finance.py:483-486`）。A 股财报有明确公告日期，应直接采用 EDGAR 那一档：以「公告日 <= as_of」过滤。可移植的具体机制是 `_as_of` 的「同一期取不晚于 as-of 的最后一次申报」（`sec_edgar.py:166-168`），对应 A 股财报的**更正/追溯调整**——同样应「从更正公告日起才生效」。`_SPANS` 的跨度校验（`sec_edgar.py:73-76`）需按一季报/半年报/三季报/年报调整区间。

**(3) 复权语义需要显式建模，TradingAgents 是隐式的。** yfinance 下载使用 `auto_adjust=True`（`stockstats_utils.py:251`），即默认前复权，且**没有把该语义写进输出契约**。A 股前复权价格随每次除权除息变化，「同一历史日期在不同 as-of 下价格不同」——与 PIT 在概念上直接冲突。Aegis 需在数据契约中显式声明复权方式，并明确技术指标基于哪种价格序列。这一项须自行设计。

**(4) 机构化错误分类需加入 A 股特有失败态。** A 股高频失败模式（涨跌停导致的缺失、停牌、代码不存在、权限/积分不足）在 TradingAgents 的三分法里没有对应位。建议扩展为 `ErrNoData` / `ErrNotObserved`（未观测窗口）/ `ErrRateLimited` / `ErrPermissionDenied` / `ErrNotConfigured` / `ErrSuspended`（停牌）。原则不变：**每一类对应一个明确的降级动作**。

### 7.3 不应照搬的部分

- **`yfinance` / Alpha Vantage 的 endpoint、参数名与字段映射**（如 `alpha_vantage_indicator.py:88-140` 的大段 `if/elif`）是 vendor 耦合代码。但其中「同一指标名下不同 vendor 支持度不同」的观察（AV 无 `mfi`，`alpha_vantage_indicator.py:37-50` vs `y_finance.py:154-158`）说明**能力契约需声明每个 Binding 支持的指标子集**。
- **`InjectedState` / LangChain 的隐式参数注入**。Eino 侧对应 `adk` middleware 与 `context.Context`，Aegis 已有 `internal/runtime/time_context.go` 的 `ContextMiddleware.BeforeAgent` 注入模式；用 `context` 传 `trade_date` 比框架特有状态注入更显式。
- **`fill_gaps` 的 `ffill().bfill()`**（`stockstats_utils.py:117-124`）：`bfill` 方向与 PIT 冲突（3.9 第 2 条），A 股停牌缺口更常见，照搬会放大问题。更合适的做法是把「缺口」作为数据契约的一部分上报，而非静默填充。
- **进程内全局可变配置单例**（`config.py:6-13` 的 `_config` + `get_config()` 深拷贝）。Go 侧应通过显式依赖注入把配置传入 Resolver。
- **`VENDOR_METHODS` 的硬编码分发表**（`interface.py:101-153`）加无消费者的 `VENDOR_LIST`（`interface.py:85-91`）。Aegis 的 Binding 是运行期注册（`docs/02-数据能力层.md:244-251`），更灵活；静态表的价值仅在编译期穷尽性检查，可用测试替代常量。
- **文本 sentinel 作为最终输出**（`NO_DATA_AVAILABLE: …`）。Aegis 有结构化契约与 `risk[]`（`docs/06-时间语义与输出契约.md:311`），应优先用字段表达失败，仅在面向 LLM 的文本渲染层退化为文案。

### 7.4 小结

TradingAgents 数据层最值得移植的不是任何一行 Python，而是五个可检验的纪律：**日期钳制放在能力边界**、**裁剪与时效校验是两件事**、**错误类型数等于路由反应数**、**配置即降级链且不静默兜底**、**「未观测」必须与「不存在」分开表达**。它最明显的空白是**交易日历**与**复权语义**，这两项恰好是 A 股数据层无法回避的部分。
