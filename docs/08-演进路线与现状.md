## 7. V2.6 Multi-Agent 职责收敛

V2.5 已收口，V2.6 的首要目标不是继续增强 Trading Agent，而是把研究职责拆回独立 Domain Agent。

### 7.1 架构约束已经冻结

新增权威文档：

- `docs/10-多Agent架构与职责边界.md`
- `docs/09-Technical数据口径.md`

后续必须遵守：

```text
Team        = 一组共同完成某类组织目标的 Role
Role        = 稳定职责
Agent       = Role 的具体运行实例
Context     = Role / Team 间结构化交接物
Capability  = Agent 所需能力
Provider    = Skill / MCP / API / DB / Crawler 等具体来源
Graph       = 公司的工作流
```

长期组织目标分为两条闭环：

```text
Online Decision Loop

Analyst Team
  ↓
Research Team
  ↓
Trading Team
  ↓
Risk / Portfolio Team
```

以及：

```text
Offline Evolution Loop

Historical / PIT Data
  ↓
Strategy Team
  ↓
Backtest / Validation Team
  ↓
ApprovedStrategy
  ↓
Regime-aware Strategy Selection
  ↓
回到 Online Decision Loop
```

禁止按来源创建 Tushare Agent / MCP Agent / Crawler Agent。

Team / Role 当前是架构边界，不立即实现通用 Registry / Factory。

### 7.5 TradingAgents 的参考边界

Aegis 借鉴 TradingAgents 的核心不是“Agent 数量”，而是公司式组织：

```text
Analysts
  ↓
Bull / Bear Researchers
  ↓
Research Manager
  ↓
Trader
  ↓
Risk Analysts
  ↓
Portfolio Manager
```

Aegis 借鉴：

- 按研究职责拆 Analyst
- Analyst / Research / Trading / Risk 分层
- 每个 Role 有独立 Tool / Capability 集
- 数据源路由位于 Tool / dataflow 下方
- Graph 统一调度
- Trader 不承担全部底层研究

Aegis 不照搬：

- 长文本 report 作为主要 Agent 间契约
- 当前立即引入 Bull/Bear debate
- 当前立即引入 Risk debate
- 在没有 PortfolioContext 时创建 Portfolio Manager
- 为了模拟公司而创建没有真实工作的 Agent

Aegis 优先使用 typed Context / Artifact。

## 8. 演进原则

```text
先确定 Role / Team 职责边界
  ↓
定义 Context / Artifact
  ↓
实现具体 Agent
  ↓
接第一套真实 Capability
  ↓
独立测试
  ↓
进入 Graph
  ↓
出现真实协作后再形成 Team
  ↓
出现第二个真实 Provider 后再抽象 routing
```

禁止反过来先造 TeamRegistry、RoleRegistry、OrganizationManager、ProviderManager 或大量空 Agent。

当前 V2.6 路线状态：

```text
TechnicalContext ✅
  ↓
Technical Agent ✅
  ↓
Technical Capability ✅
  ↓
Technical integration ✅
  ↓
Market → Technical → Trading ✅（代码与单测）
  ↓
Hosted V2.6 Pipeline ✅（可由 GitHub Actions 手动执行）
  ↓
Full Market Agent E2E ✅（本地真实验证通过）
```

只有 Analyst 维度增长到足以让 Trader 过载时，再引入 Research Team / InvestmentThesis 层。

策略与回测属于独立长期方向：

```text
Strategy Team
  ↓
StrategyCandidate
  ↓
Backtest / Validation Team
  ↓
ValidationReport
  ↓
ApprovedStrategy
```

原则是策略研发与验证分离；生产环境只从已验证策略集合中按当前 regime 选择，不在实时路径中无限调参追逐“最优”。

## 2026-10-08 产品边界补充

Aegis 是研究与决策辅助系统，**永不接入真实下单、券商订单或交易审批流程**。
组合金额推演、风险预算与策略回测均为研究用途；参见权威架构文档 `docs/10-多Agent架构与职责边界.md` 的“永久产品边界”。
