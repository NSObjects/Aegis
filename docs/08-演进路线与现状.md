```text

```

该协议差异不会泄漏到 Market / Trading Agent。

## 6. 当前明确不做

为了保持架构可验证，当前阶段不引入：

- 多 Provider
- MCP
- Capability Registry
- Provider Registry
- Reflection Agent
- Risk Agent
- Memory
- 多分支 Graph
- 自动重试/Repair Graph
- 交易执行
- BUY / SELL 输出

这些能力只有在下一阶段出现明确需求时再实现。

## 7. V2.6 Trading 数据契约

V2.5 已收口，V2.6 已开始。

第一步已经完成：

- 新增 `docs/09-Trading数据口径.md`
- 固定 requested_as_of / effective_as_of 语义
- 区分非交易日与个股停牌
- 技术指标统一采用截至 as_of 的 PIT_QFQ
- 固定 120 个交易日基础窗口
- 固定 MA / RSI / MACD / 收益率 / 量能的确定性计算口径
- 区分必需数据与可选增强数据
- Trading Prompt 已同步这些约束

下一步只做：

1. 在 Tushare Skill 中实现确定性 stock research 脚本。
2. 独立验证时间裁剪、停牌状态、PIT_QFQ 和指标结果。
3. 脚本稳定后再让 Trading Agent 优先消费该结构化结果。
4. 暂不新增 Agent 或 Graph 分支。

原则仍然是：

```text
先有真实需求
  ↓
再新增能力
  ↓
每一步独立测试
  ↓
最后进入 Graph
```
