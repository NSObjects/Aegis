## 7. V2.6 Multi-Agent 职责收敛

V2.5 已收口，V2.6 的首要目标不是继续增强 Trading Agent，而是把研究职责拆回独立 Domain Agent。

### 7.1 架构约束已经冻结

新增权威文档：

- `docs/10-多Agent架构与职责边界.md`
- `docs/09-Technical数据口径.md`

后续必须遵守：

```text
Team        = 一组共同完成某类组织目标的 Role
Role        = 稳定职责
Agent       = Role 的具体运行实例
Context     = Role / Team 间结构化交接物
Capability  = Agent 所需能力
Provider    = Skill / MCP / API / DB / Crawler 等具体来源
Graph       = 公司的工作流
```

长期组织目标分为两条闭环：

```text
Online Decision Loop

Analyst Team
  ↓
Research Team
  ↓
Trading Team
  ↓
Risk / Portfolio Team
```

以及：

```text
Offline Evolution Loop

Historical / PIT Data
  ↓
Strategy Team
  ↓
Backtest / Validation Team
  ↓
ApprovedStrategy
  ↓
Regime-aware Strategy Selection
  ↓
回到 Online Decision Loop
```

禁止按来源创建 Tushare Agent / MCP Agent / Crawler Agent。

Team / Role 当前是架构边界，不立即实现通用 Registry / Factory。

### 7.2 当前代码与目标架构的差距

当前已验证的 V2.5 仍然是：

```text
Market Agent
  ↓
MarketContext
  ↓
Trading Agent
  ↓
Decision
```

因此当前 Trading Agent 还承担了部分“自行补充个股数据”的过渡职责。

这属于**待拆分的 V2.5 遗留职责**，不是长期设计。

此前 V2.6 曾尝试让 Trading Agent 固定调用 `stock_research.py`。该方向已经被否定：

```text
Trading Agent → stock_research.py     ❌
```

```text

  ↓

  ↓
Skill / Tushare / MCP / DB / API
  ↓

  ↓

```

`stock_research.py` 可以作为 Technical Capability 的第一套确定性实现，但不能成为 Trading Agent 的架构依赖。

### 7.4 数据源原则

不同 Agent 可以使用不同数据来源：

```text
Technical Agent
├── Tushare

News/Event Agent
├── News API

├── Tushare

```

Graph 和 Trading Agent 不感知具体来源。

### 7.5 TradingAgents 的参考边界

Aegis 借鉴 TradingAgents 的核心不是“Agent 数量”，而是公司式组织：

```text
Analysts
  ↓
Bull / Bear Researchers
  ↓
Research Manager
  ↓
Trader
  ↓
Risk Analysts
  ↓
Portfolio Manager
```

Aegis 借鉴：

- 按研究职责拆 Analyst
- Analyst / Research / Trading / Risk 分层
- 每个 Role 有独立 Tool / Capability 集
- 数据源路由位于 Tool / dataflow 下方
- Graph 统一调度
- Trader 不承担全部底层研究

Aegis 不照搬：

- 长文本 report 作为主要 Agent 间契约
- 当前立即引入 Bull/Bear debate
- 当前立即引入 Risk debate
- 在没有 PortfolioContext 时创建 Portfolio Manager
- 为了模拟公司而创建没有真实工作的 Agent

Aegis 优先使用 typed Context / Artifact。

## 8. 演进原则

```text
先确定 Role / Team 职责边界
  ↓
定义 Context / Artifact
  ↓
实现具体 Agent
  ↓
接第一套真实 Capability
  ↓
独立测试
  ↓
进入 Graph
  ↓
出现真实协作后再形成 Team
  ↓
出现第二个真实 Provider 后再抽象 routing
```

禁止反过来先造 TeamRegistry、RoleRegistry、OrganizationManager、ProviderManager 或大量空 Agent。

当前近期路线仍然不变：

```text
TechnicalContext ✅
  ↓
Technical Agent
  ↓
Technical Capability
  ↓
Market → Technical → Trading
```

只有 Analyst 维度增长到足以让 Trader 过载时，再引入 Research Team / InvestmentThesis 层。

策略与回测属于独立长期方向：

```text
Strategy Team
  ↓
StrategyCandidate
  ↓
Backtest / Validation Team
  ↓
ValidationReport
  ↓
ApprovedStrategy
```

原则是策略研发与验证分离；生产环境只从已验证策略集合中按当前 regime 选择，不在实时路径中无限调参追逐“最优”。
