# V2.11.2 — 已观测账户估值与持仓敞口

> 目标：从调用方真实提供的、完整对账的账户资产快照计算**当前**敞口，作为 Risk Analyst 的可验证输入。不是自动资金同步、仓位建议或交易授权。

## 为什么需要这一步

V2.11.1 仅验证账户快照是否在用户指定的有效时间窗内；原有 `positions[].quantity` 只有股数，无法证明市值、现金或持仓权重。Risk Analyst 不应根据股数猜测“占总资产 20%”。

V2.11.2 允许账户方**可选**提供 `valuation`。若不提供，系统继续运行原来路径，但 `observed_exposure` **不存在**，不把未知敞口误写为零。

## JSON 输入示例（字段定义示意，非真实账户）

```json
{
  "state": "POSITIONS",
  "as_of": "2026-10-08T09:00:00+08:00",
  "positions": [
    {"symbol": "600519.SH", "quantity": 100},
    {"symbol": "000001.SZ", "quantity": 200}
  ],
  "valuation": {
    "scope": "CASH_AND_POSITIONS",
    "currency": "CNY",
    "total_value_fen": 100000,
    "cash_fen": 30000,
    "position_values": [
      {"symbol": "600519.SH", "market_value_fen": 60000},
      {"symbol": "000001.SZ", "market_value_fen": 10000}
    ]
  }
}
```

这些数字**只是展示格式的示例**，不代表现实行情或账户。所有金额单位均为人民币**分（fen）**，必须是整数；上例中的 100000 分就是 1000 元。不要将浮点元直接作为分传入。当前仅支持单一币种 CNY。

`scope = CASH_AND_POSITIONS` 表示 `total_value_fen` 是 **cash_fen + 所有已列示仓位的 market_value_fen**，不含负债、融资融券、其他资产、在途委托等项目；其他类型账户不得冒充这个估值范围。调用方必须保证 `as_of` 对应**同一次一致性观察**，本地校验不能证明外部来源真实或估值新鲜。

## 严格契约

- `NOT_PROVIDED` 不得出现 `valuation`；该状态不等于已观测空仓。
- `EMPTY` 可以携带仅现金的估值；所有 `position_values` 必须为空。允许 `total_value_fen=0`，但此时百分比没有定义。
- `POSITIONS` 携带估值时，每一个 `positions[].symbol` 都必须有且只有一个匹配的 `position_values`。不可遗漏、重复或额外增加不存在的股票。
- 现金、市值及总额均非负；求和时检查 `int64` 溢出。必须 **精确对账**，不接受任何未解释余额。带持仓且估值总额为零会被拒绝。
- 快照 `as_of` 和可选的 `-portfolio-max-age` 依然执行 V2.11.1 的 PIT / 时效校验。
- `portfolio.ComputeExposure` 使用精确整数计算，`weight_bps = floor(market_value_fen / total_value_fen * 10000)`。权重单位是基点，10000 = 100%。向下截断可能导致各项权重合计略小于 10000，不得据此生成虚假“缺失资金”。
- 未提供估值时，`ComputeExposure` 返回 `nil`。已提供**零价值空账户**时返回明确的零总资产且比例未定义（`cash_weight_bps` 不出现）。

## 集成边界

现有 `-portfolio-file` 可直接解析可选估值；没有新数据源、新 API Key 或假账户默认值。

```text
用户观察账户 / 外部明确提供 JSON
           ↓
  PortfolioContext 验证 / 时效验证
           ↓
  估值对账、当前敞口确定性计算
           ↓
  ResearchArtifact / Debate / Trader
           ↓
  Risk Analyst ← 真实 PortfolioContext + observed_exposure
           ↓
  PortfolioDecision（仍不可执行）
```

完整工作流输出的 `portfolio_review.observed_exposure` 仅在估值存在时出现。Risk Analyst 收到这一字段时可以基于它分析**当前**权重；没有该字段时不得推断现金、市值、集中度。实际模型文本中的引用仍应审查，不应仅因输入可信就推定所有自然语言结论都被完全校验。

本阶段**不实现**：资金划转、可买额度、下单数量、风险预算、持仓上限自动审批、实时行情估值、券商账户同步、杠杆或盈利能力预测。要分析**交易后**集中度，必须先获得明确的拟下单规模、价格与适当的限制条件，不能由当前持仓权重反推交易建议。

## 验收条件

1. 账户对账、重复/虚构/缺失持仓市值、负数、溢出、非整数金额及零账户的确定性单测。
2. Portfolio Review 仅在合法估值存在时输出 `observed_exposure`，不改变旧的非执行决策规则。
3. Risk Analyst 的 LLM 输入可核对来源于实际观察的精确敞口，未提供金额时不出现此字段。
4. 严格 CLI JSON 解析仍拒绝未声明金额字段；错误数据在任何模型/研究调用前被拒绝。
5. 现有使用 `{"state":"NOT_PROVIDED"}` 的 Production CLI Hosted 路径不应要求估值，也不会因缺失金额报“零敞口”。
