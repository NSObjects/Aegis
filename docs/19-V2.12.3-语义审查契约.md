# V2.12.3 — 可选语义审查任务与建议性结果契约

> 目标：为未来的人类复核或独立模型复核建立**可审计的输入/输出边界**。当前版本没有实现语义审查模型，不执行任何语义判断，也不修改 PortfolioReview 默认流程。

## 研究链路中的位置

```text
ResearchArtifact + DebateState + ResearchPlan
  └─ evidenceledger.Build（现有严格验证）
       └─ semanticreview.BuildTasks（显式 Insight → 论点关联）
            └─ Tasks（按 Insight、关联 ID 原顺序排列）
                 └─ 未来可选 Reviewer / 人工分析（V2.12.3 不实现）
                      └─ Report（外部输入，必须 ValidateReport）
```

该分支独立于 `TradeIntent`、`RiskContext`、`PortfolioDecision`，不产生订单、审批或任何券商请求；V2.12.3 **不在默认运行链中构造 Report**。

## BuildTasks 的输入规则

- 只接受经过现有 `evidenceledger.Build` 校验的 Artifact、Debate、ResearchPlan 组合；非法 ID、标的或引用应先被原有 Validator 拒绝。
- 一个显式 `insights[].argument_ids[]` 关联产生一条 Task。同一 Argument 被不同 Insight 引用时可以有多条 Task；身份由 `insight_index` 与 `argument_id` 的**有序组合**定义。
- Task 保留 Insight 的种类与原始 `claim/references`，以及 Debate 论点的 `side/claim/references`；引用数组与输入分离拷贝。
- `reference_alignment` 来自 V2.12.2，只表示结构化引用重合程度（同事件 / 同领域 / 无共同引用），**不构成语义判断**。
- 没有显式关联则产生 0 条 Tasks；不会自动从自然语言猜测引用，不会凭领域相同生成“支持”。

## 独立的建议性 Review Report

未来可选 Reviewer 或人工复核可提供 `Report`，结论只能为：

| Verdict | 语义 |
|---|---|
| `CONSISTENT` | 审查者认为两条陈述在相关语境下相容；**不是被验证的事实** |
| `CONTRADICTORY` | 审查者认为两条陈述存在语义矛盾；仍需追溯原始证据 |
| `UNCERTAIN` | 无法确定；必须写出 `limitations`，不强迫二选一 |

所有 Finding 必须附 `rationale`，并按 Tasks 顺序**完整且一一对应**。不得添加未知 `argument_id`、改变 `insight_index`、重复结果或遗漏任务。

`ValidateReport` 只执行**结构、身份、枚举与解释字段**校验；成功并不表示评论真实、正确、完整或可信。将模型输出冒充人工结论，也不属于这一函数能够检验的内容。

## 明确不做的事

- 不调用 LLM、Web Search、行情或外部 Provider，不增加 Token/网络成本。
- 不将 `SAME_EVENT_ID` 自动映射为 `CONSISTENT`，也不将 `NO_SHARED_REFERENCE` 自动映射为 `CONTRADICTORY`。
- 不因审查结果改变 Manager Plan、TradeIntent、Risk 或 PortfolioDecision；不引入任何实际交易执行路径。
- 不声称模型审查已实现、不进行真实研究数据端到端语义准确率评测。

下一增量若实现 Reviewer，应独立设计模型输入净化、提示词/契约、超时和失败处理、无法判断时的降级、成本限额及测评集；任何将报告接入正式 Workflow 的改动必须单独审查。

## 运行验证

确定性测试应覆盖任务顺序、复制语义、非法上游输入、无显式关联、报告遗漏/重复/串改任务、非法 Verdict、空 Rationale、UNCERTAIN 缺少局限说明。常规 PR CI 执行 Go Vet、全部 Go Tests 和 CLI 输入门禁。
