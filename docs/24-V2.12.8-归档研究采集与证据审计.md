# V2.12.8 — 已归档研究结果的样本采集与证据审计

> 本阶段实现真实产物**格式**的离线采集、来源字节完整性和 PIT 审计门禁；仓库目前没有可认证的真实人工标注集。新增测试使用虚构材料，**不是实盘研究或模型质量证据**。

## 输入与使用

`research.CaptureArchivedResearch` 接收已经由 Aegis 完整 `FullPortfolioWorkflow` 生成并**原样保存**的 JSON 字节，而不是再调用 LLM 或爬取来源；另需提供从外部可信归档独立保存的来源证据字节。

```go
candidate, err := research.CaptureArchivedResearch(research.ArchivedResearchInput{
    SampleID: "independent-sample-id",
    ResearchJSON: savedFullPortfolioResultBytes,
    ResearchSHA256: independentlyPinnedResearchHash,
    EvidenceBytes: separatelyArchivedEvidenceBytes,
    Source: semanticreview.CurationSource{
        EvidenceRef:    "archive://source/immutable-object-id",
        EvidenceSHA256: independentlyPinnedEvidenceHash,
        EvidenceAsOf:   "2026-09-23T12:00:00+08:00",
        CapturedAt:     "2026-09-23T13:00:00+08:00",
        RequestedAsOf: "2026-09-23T15:00:00+08:00",
    },
})
if err != nil { return err }
// candidate.Tasks 是等待人工盲标的结构化工作项，不含 Gold。
// 外部系统分组、分区、保管并分发盲标材料；有完整两人标注及
// 分歧仲裁记录后，才构造 CurationSample 交由 FreezeCuration 校验。
```

示例只是字段说明，**不能以人工写入的时间戳或哈希字符串替代真实原始档案**。

### 两类快照必须区分

| 快照 | 定义 | 哈希校验 |
|---|---|---|
| `ResearchJSON` | Aegis 已完成的完整 `FullPortfolioResult`，可在研究截止后保存 | `ResearchSHA256` 与原始字节相符 |
| `EvidenceBytes` | 对应原始证据的独立归档字节（具体内容与引用关系由外部审计者核查） | `Source.EvidenceSHA256` 与原始字节相符 |

`Source.CapturedAt` **明确表示证据归档采集时间**，不是最终研究产物的生成/保存时间。证据的声明时序仍须满足 V2.12.7 的严格策略：

```text
EvidenceAsOf <= CapturedAt <= RequestedAsOf
```

例如在 15:00 研究截止时，16:00 生成并保存完整研究结果可以接受，但其中所有**用于证明截止时可见信息的证据档案**必须有可审计的更早来源。只有 16:00 才首次抓到、无法证明在 15:00 可见的证据，不可修改记录时间“补齐” PIT。事件 Context 中如果显式给出 `evidence_as_of`，也不得晚于同一研究截止时点。

注意此校验只证实调用方提交的字节与期望散列匹配，且声明的时间满足顺序关系，**不能证明外部来源真实性、归档不可篡改、文档首次公开时间，亦不能证明该字节的内容真的支持模型论点**。期望哈希必须在读取本次数据之前由独立可信仓库固定，并审计证据到各引用的对应关系。

### 确定性结构检查

- 研究 JSON 单值、严格解析，不允许额外字段或尾随多份 JSON；研究及证据字节均有大小上限。
- 必须包含真实生产输出结构的 `ResearchArtifact`、`PortfolioReview`、Debate、ResearchPlan、EvidenceLedger、TradeIntent、RiskContext、PortfolioDecision；不接受残缺流程冒充已完成研究。
- 调用当前 `manager.Validate` / `evidenceledger.Build` 重新验证研究输入；重建 Ledger 必须与归档中的 Ledger 完全一致，否则拒绝。
- 研究截止时间必须与 `EventContext.RequestedAsOf` 完全指向同一瞬间。
- 从**原有明确的** `Insight → Argument` ID 链生成 `semanticreview.Tasks`，没有明确可审阅链接即拒绝，不自动由语义相似度造链接。
- 输出仅为 `ResearchSampleCandidate`（任务及来源元数据），没有 `Gold`、`ExpectedVerdict`、任何标注人或审核状态，**不能直接充当 HUMAN_REVIEWED 数据集**。

### 接入人工治理与测评

```text
已保存的实际 FullPortfolioResult + 有独立归档的证据字节
                    ↓
        CaptureArchivedResearch
                    ↓
         UNLABELED Candidate
                    ↓
独立验证来源 / PIT / Evidence→Claim 对应关系
                    ↓
人工决定 leakage_group 与 DEVELOPMENT / HOLDOUT 分组
                    ↓
两位真正独立的盲标者提交逐任务判断
                    ↓
分歧由第三人仲裁，形成 CurationSample
                    ↓
        FreezeCuration（V2.12.7）
                    ↓
隔离 Holdout Gold，模型只见 Tasks，独立记录实际预测
                    ↓
        EvaluateRun / CheckQuality（V2.12.6）
```

该采集器**不会自动给出** `split`、`leakage_group`、人类身份和 Gold，避免源于同一事件、同一研究请求的样本意外跨数据集泄漏。不同来源字节并不保证语义内容不同，真实实验仍需人工近重复去重。

## 验收

对带合成 fixture 的真实 `FullPortfolioResult` JSON 形状做单测，验证：独立双哈希、被篡改的输入、无效源时间、事件截止不匹配、错误 Ledger、引用不存在、残缺研究结果、无显式链接、伪造 JSON 和 Gold 不可自动生成。CI 使用标准 Go vet、全量 Go test 和 CLI 输入门禁，无网络、无 LLM、无 API Key。

**剩余必须执行的真实工作**：采集首份可审计研究快照，独立保存来源文档，核实发行/抓取/PIT 时间，进行真实双人标注及仲裁，并保管外部签名或受控归档。没有这些步骤不得宣称真实 Holdout 已完成。
