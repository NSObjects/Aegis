# V2.12.7 — 研究样本盲标、仲裁与离线数据集冻结

> **本阶段仅交付数据治理流程及合成测试。** 未采集真实研究样本，未聘请或认证标注员，未运行真实 Reviewer，也没有声称真实准确率或模型达到了部署标准。Aegis 永久是研究与决策辅助系统，不提供下单、审批或自动执行。

## 背景：V2.12.6 不足在哪里

V2.12.6 的 `EvaluationDataset{Provenance:HUMAN_REVIEWED}` 只需要 `evidence_ref` 和两个不同的 `annotator_ids`：这些元数据不表示两人真正独立盲标，也没有记录**如何**就同一任务达成 Gold Label。为了不把“自报的两个人名”当成独立测评，本阶段新建独立的**数据集生产**流程，而不改写旧的离线计分器或把它接入交易链。

## API 和输入来源

Go 包：`internal/research/semanticreview`。

```go
frozen, err := semanticreview.FreezeCuration(curation)
if err != nil { return err }
// 将 frozen.CorpusJSON、DevelopmentJSON、HoldoutJSON 和 Manifest
// 写入受控、不可覆盖的归档存储；这一步由调用方负责。
if err := semanticreview.VerifyFrozenCuration(frozen); err != nil { return err }
holdout, err := semanticreview.ReadFrozenDataset(frozen, semanticreview.SplitHoldout)
if err != nil { return err }
// 仅在正式评测流程中，向独立、未见过 Gold 的评估器提供 holdout.Tasks。
// Gold 不能被并入模型输入或提示词调优记录。
// 在获得独立模型预测记录之后才能调用 EvaluateRun / CheckQuality。
```

每个 `CurationSample` 都必须提供：

- `id`（全局唯一）、`split`（`DEVELOPMENT` / `HOLDOUT`）、`leakage_group`（同一事件、新闻、研究请求或复用材料应使用同一泄漏组；不能跨分区）；
- 已经形成的 `Tasks`；保留原始论点、引用、类别和顺序，不自动推断语义结论；
- `Source`：`evidence_ref`（归档来源定位）、`evidence_sha256`（归档资料的 SHA-256 小写 hex）、`evidence_as_of`、`captured_at`、`requested_as_of`（RFC3339）；
- **恰好两份** `AnnotationAttestation`，每份给出稳定、不同的 `annotator_id`、逐任务对齐的完整 `labels`，并分别声明 `blind_to_model=true`、`blind_to_peer=true`；
- 仅对两位标注员存在分歧的任务，按任务顺序提交一条 `Adjudication`，必须是不同于两位标注员的第三人 ID、有理由、有完整的任务身份和有效 Verdict。达成一致的任务不能额外加入不必要的仲裁。

标签只能是 `CONSISTENT` / `CONTRADICTORY` / `UNCERTAIN`。出现分歧时必须人工仲裁，不能以多数投票、引用重合或模型的预测自动生成金标准；本组件不接受 `Report` / 预测作为 Gold 输入。

## PIT 与样本泄漏检查

严格的默认 PIT 策略为：

```text
evidence_as_of <= captured_at <= requested_as_of
```

这里使用真实时间而不是字面字符串排序；任何一项时间无效或违反规则都会失败。特别注意：**研究截止后补抓的历史内容不会因此自动变成当时可见的 PIT 数据**。这类回填必须另做独立审计与带档案证据的处理流程，不能通过改时间字段绕过。

同一 `leakage_group` 或相同 `evidence_sha256` 的材料不能横跨 Development 与 Holdout。这只能覆盖已登记的重复材料；语义相似却未同组的样本仍需要人工排查。

冻结前两组都必须非空，且所有 `Tasks`、身份、标签和元数据结构校验成功；任何单一失败都不会返回部分数据集。Development / Holdout 分别导出为现有 `EvaluationDataset`，版本独立标记为 `<version>-development` / `<version>-holdout`。

## 冻结与完整性边界

`FrozenCuration` 包含原始 curation、两份派生数据集的**序列化字节**及 `FreezeManifest`：

- `corpus_sha256`：包含两份声明、仲裁记录和来源字段的完整输入快照哈希；
- `development_sha256` 与 `holdout_sha256`：精确派生 JSON 字节哈希；
- 两组样本数、仲裁任务数，以及数据集版本。

`VerifyFrozenCuration` 重新从原始冻结 JSON 生成 Gold 与分区，并逐字节核对三份数据和清单。不能把整个 bundle 连同 Manifest 一起替换却仍称为原始冻结版；**必须由外部受控存储、版本权限及独立保存的 Manifest 哈希形成真正的归档保护**。本工具不提供电子签名、人员实名认证、外部文件存在性检查或加密隔离。

`ReadFrozenDataset` 返回**新的解码副本**，避免调用方编辑后的指针污染冻结数据。但它并不控制谁能读取 Holdout 标签。正式盲评必须通过外部权限限制，把 Tasks 给模型运行方，把 Gold 留在独立评测服务；不得把同一份 Holdout 用于调参、示例提示词或反复选择模型。

## 真实测评前必须由人完成

1. 固化真实来源及其散列、时间戳，核验材料确实可在研究截止前取得；
2. 用稳定的泄漏分组独立确定 Development / Holdout，人工抽查近似重复；
3. 分别向两位人类标注员分发看不到模型预测和他人标签的材料；存留可审计的外部提交记录；
4. 分歧由第三人依据原始证据仲裁；不能复用同一模型的输出当答案；
5. 冻结、存储、单独控制 Holdout，才运行独立模型并保存实际响应、耗时和 Token 计量。

**本 PR 的测试数据全部是虚构样本和虚构人员 ID**，只能说明校验、仲裁、版本隔离及哈希重算逻辑能工作。即使未来 `CheckQuality` 返回 `PASS`，也不能证明人类身份、证据真实、模型值得信任或策略可以执行交易。

## 回归与发布边界

`go test ./...` 覆盖：两人一致、分歧仲裁、确定性冻结、读回与篡改检测、PIT 不合法、来源与泄漏组跨分区、ID 冲突、缺失/冒充盲标，以及错误的仲裁身份和顺序。CI 不需要 API Key，无联网、无模型调用，不改 CLI、PortfolioReview、RiskContext 或 PortfolioDecision。
