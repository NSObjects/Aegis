# V2.11.3 — 调用方风险策略与当前组合限制检查

> 本阶段只检查**已观察到的当前持仓**是否超过调用方明确声明的限制。该结果是有证据的风险诊断，不是委托、买卖许可、订单额度或交易后头寸预测。

## 1. 两个互相独立的输入

- **PortfolioContext / valuation**：账户观察事实，来自调用方实际提供的 `-portfolio-file`；其数量/人民币分必须按 V2.11.2 校验，`as_of` 受 V2.11.1 的时效约束。
- **RiskLimits**：另一份调用方定义的业务策略，使用独立的 `-risk-limits-file`。定义限制不意味着券商认可或真实性已核查；它也不属于账户资产事实。未来可以从经过身份与版本验证的配置库中加载，但本阶段只接受明确文件输入。

为防止模型生成虚构限额，系统**没有默认风险预算**。不传文件时不进行风险限制检查，也不伪造 `PASS`。

## 2. 风险策略 JSON（格式示例，数值非投资建议）

```json
{
  "policy_id": "user-rulebook-v1",
  "as_of": "2026-10-08T09:00:00+08:00",
  "scope": "CASH_AND_POSITIONS",
  "currency": "CNY",
  "rules": [
    {"kind": "MAX_SINGLE_POSITION_WEIGHT", "limit_bps": 3000},
    {"kind": "MAX_INVESTED_WEIGHT", "limit_bps": 8000}
  ]
}
```

这里 3000 / 8000 只演示结构（单位 bps，10000 = 100%），不是系统建议的限制值。

`as_of` 是调用方声明该策略适用的时间点，不得晚于研究的 `RequestedAsOf`；不能从未来策略判断过去的组合。系统不验证策略签名、批准人、启停与废止时间——这是后续版本的治理要求。

## 3. 严格契约

| 项目 | 业务规则 |
|---|---|
| 策略 ID | 必须非空 |
| 时间 | RFC3339、不能晚于研究截止 |
| 范围 | 只支持 `CASH_AND_POSITIONS` |
| 币种 | 只支持 `CNY` |
| Rule | 至少一条，类型不得重复 |
| `limit_bps` | 必须显式存在、为 0–10000 的整数；`0` 是有效的严格限制，不是缺失 |
| `MAX_SINGLE_POSITION_WEIGHT` | 检查所有持仓的最大当前市值比例 |
| `MAX_INVESTED_WEIGHT` | 检查当前总持仓市值占已观测现金+持仓总值的比例 |

使用**未取整的整数分值比例**做超限判断：只有 `value_fen × 10000 > total_value_fen × limit_bps` 才判定 `BREACH`，相等为 `PASS`。计算中用大整数避免 `int64` 乘法溢出。输出的 `observed_weight_bps` 供阅读使用，仍向下截断；不能拿展示数字反算有没有超限。

检查结果仅有：

- `PASS`：有正的、合法对账总值，且当前金额未超过阈值；
- `BREACH`：当前金额明确超过至少一个策略上限；
- `INSUFFICIENT_DATA`：账户未提供估值或已观测账户总值为零，当前比例没有可靠分母。**不是 PASS，也不代表违反策略**。

完整工作流在 `current_limits_review` 中输出独立检查结果（`policy_id`、策略和账户时间、每条规则的限额、当前展示权重和状态）。**不修改** Research / Debate / Trading / Risk Agent 现有职责；RiskContext 和 PortfolioDecision 的不可执行状态契约仍保持。当前超限诊断也不等于对一个未给出买卖方向、拟成交价及交易数量的计划进行事前审批。

为避免 V2.11.2 后的旧摘要在已有账户金额时仍声称“现金未知”，`PortfolioDecision` 对 `CANDIDATE + ACCEPTABLE` 会区分两种仍需人工审查的状态：

- 无已观测估值：`REVIEW_REQUIRED / ACCOUNT_DATA_ABSENT`。
- 有已观测估值：`REVIEW_REQUIRED / RESEARCH_REVIEW_REQUIRED`，因为组合影响和风险解释仍需研究复核。

这两种原因码都**不是**对新订单的批准。独立的 `current_limits_review` 仍只诊断现有持仓，不得反向理解为交易限制已由 Risk Agent 全面执行。


## 4. CLI

在同一个显式提供的账户快照上：

```bash
go run ./cmd/aegis \
  -symbol 600519.SH \
  -portfolio-review \
  -portfolio-file ./portfolio.json \
  -portfolio-max-age 24h \
  -risk-limits-file ./risk-limits.json
```

上面的 24 小时仅为调用方配置示例，非通用账户时效规则。风险策略文件缺失则保持原有行为；传入此文件必须启用 `-portfolio-review`。

严格 JSON 解码拒绝未知字段、null 根、额外 JSON 值、非法币种/范围、非法限额、重复 Rule。输入校验及策略 PIT 检查在应用创建模型和数据源前执行。完整 Workflow 对库调用也进行同样的前置校验，不能只依赖 CLI。

## 5. 验收边界与后续

- 对账存在时返回确定性的 `PASS/BREACH`，比率边界采用精确金额而非展示权重。
- 无估值或总资产为零时明确返回 `INSUFFICIENT_DATA`。
- 未来策略、格式错误、重复 Rule 在调用任何 Agent 前失败。
- 原有不传风险限制文件的生产 CLI `NOT_PROVIDED` 路径不变。
- 目前**不**计算未来的交易后头寸、持仓可买量或价格滑点；交易审批仍需真实的方向、数量、价格与交易/资金约束，以及策略治理、交易日历与经验证的账户数据源。
