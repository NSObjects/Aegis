### 执行和状态更新规则

1. **仅以顶部「下一项」作为默认开发入口**。进入对应 Rn 小节，按 Rn-01 → Rn-02 顺序挑第一条没有勾选的任务；开工前查看 main/开放 PR，已经实现的功能只验收，不重复开发。
2. 一个 Issue 负责一个可验证交付；一个 PR 尽量解决单个纵向功能缺口，写明测试与固定 SHA。不可将规划表中「PLANNED」当成缺少全部代码的证明。
3. **只有勾选全部必要任务、满足 Exit Gate 且记录真实验收证据**，才能改阶段为 DONE，并把顶部「现在/下一项」更新到后一阶段。
4. 阻塞项标为 BLOCKED，附复现/解除条件；非阻塞优化进入 Issue backlog，不反复打磨细节拖延主线。
5. R7 仓位管理**不能偷跑到 R1～R6 的完成条件**。若后续调整优先级，先写明变更原因、前置条件与下一任务，再修改执行顺序。
6. 状态枚举：PLANNED / IN_PROGRESS / IN_REVIEW / DONE / BLOCKED / DEFERRED。

**定位**：R1 不是「在网页上显示一个 Agent 流程图」，而是用户日常研究股票的主要工作环境。**本阶段必须做完基础研究操作、研究过程、报告和历史闭环，才能进入 R2 对话研究**；动态仓位管理属于独立大型 R7，不阻塞本阶段。

### R1 用户完整路径（作为验收脚本的主线）

~~~text
登录 Aegis Web
   ↓
搜索 / 选择股票代码（研究标的工作区）
   ↓
设定研究截止时间与必要选项 → 开始研究
   ↓
研究任务 RUNNING（可离开页面后回来）
   ↓
实时查看各 Agent 进度、工具/数据来源、失败或不足状态
   ↓
打开结构化研究报告
   ├─ 市场 / 技术 / 事件 / 可用时基本面
   ├─ Bull / Bear 观点、反驳、未解决分歧
   ├─ Research Manager / TradeIntent
   ├─ Risk / Portfolio 已有确定性审查
   └─ 证据来源、有效时间、数据缺口、运行版本
   ↓
查看同标的历史研究、比较两次研究的实际变化
   ↓
保存/导出报告或再次研究，并可回到任务详情
~~~

**注意**：R1 是结构化 Web 操作，不要求用户会用聊天。聊天发起研究、追问报告、工具路由和长期对话上下文是 **R2**，不能用它们阻碍 R1 上线。现有 Portfolio/Risk 的 REVIEW_REQUIRED/BLOCKED/不足输入应该如实显示，**不假装 R1 已经有动态仓位系统**。

### R1 Exit Gate（必须全部验证）

1. **研究可操作**：网页能独立完成一次真实 Multi-Agent 研究和一次重试/取消；任务运行可查询，不依赖浏览器连接存活。

## R5 — 连续研究：Thesis Tracker、后验验证与研究 Memory

> Memory 不是行情/新闻存储和聊天记录替代品。行情由独立来源提供；本阶段存储的是 Agent **此前判断、研究假设、历史错误与反思**，并将它们与实际后验数据连接。

- [ ] **R5-01 研究假设结构化**：hypothesis_id、标的/as_of、正反证据、有效期、失效条件、验证规则、原始 run_id。
- [ ] **R5-02 后验观察和假设验证**：历史原文不可覆盖；真实行情/事件到来后判定 SUPPORTED/REFUTED/INCONCLUSIVE/EXPIRED，不能将缺失数据判为正确。
- [ ] **R5-03 错误类型/原因归档**：区分数据缺失、引用错误、论证偏差、环境变化及事后回顾偏差；反思引用原判断和后续事实。
- [ ] **R5-04 Research Memory 读写/检索**：按标的、研究论点、市场阶段、失败类型检索成功与失败样本；支持来源引用和撤销；RAG/向量库视实际需要引入。
- [ ] **R5-05 会话与自动研究集成**：可以回答「昨天观点还成立吗」「以前为什么判断错？」并追溯记录；Memory 不替代实时数据或确定性风控。
- [ ] **R5-06 连续研究实际验收**：同一股票跨日期形成可审计历史，至少一个假设被后验观察验证或标为未知，记录错误归因的支持与反例。

**R5 Exit Gate**：形成真实的跨日研究能力，而不只是会话记忆；下一项 **R6-01**。

## R6 — 独立策略回测与研究效果评估

**目标**：为后续复杂仓位策略提供可靠测评基础，但这里的回测并不依赖新增 Position Sizing Engine。

- [ ] **R6-01 数据时间语义与历史重放**：严格 PIT、当时可交易股票池、复权/交易日历、停牌及数据缺失。
- [ ] **R6-02 策略定义版本化**：将 R3 的规则及参数固化为可复现 StrategyCandidate，建立同版本相同输入可重放的测试。
- [ ] **R6-03 确定性回测计算**：记录信号、模拟持有、交易费用/滑点、T+1/涨跌停/流动性约束；不接真实券商执行。
- [ ] **R6-04 独立验证与报告**：样本内/外、滚动或 Walk-forward、市场环境拆分、收益回撤/换手/误判；Strategy Team 不自行批准自己的策略。
- [ ] **R6-05 研究质量回溯**：区分方向判断、候选筛选、数据质量与时点偏差；将可证实的反馈提供给 Research Memory，而不是覆盖旧结论。

**R6 Exit Gate**：研究规则可进行独立、可复现的历史和样本外验证。**下一项 R7-01，但启动 R7 前再次核对优先级：若研究工作台仍有阻断性功能缺口，先修研究核心；不可因为原计划有仓位就提前启动。**

## R7 — 大型独立功能：Portfolio & Position Management（非近期主线）

**地位**：专门规划、单独启动的大型 Epic。**不是 R1 工作台的一个表格，也不是 R2 的一个聊天 Tool**。只有研究工作台、研究历史与基础评估已经稳定、需求/真实账户数据准备齐全时再开始。已有的 Risk Analyst、Portfolio Manager、限额/估值/What-if 在此之前仅按**现有边界**运行。

**产物目标**：把组合资金、持仓风险、账户预算、市场环境、研究意图、不同仓位政策、What-if 和模拟验证组成完整的研究性组合决策系统；永不真实下单。

### R7-A：组合领域与观察数据

- [ ] **R7-01 设计 Portfolio 独立领域模块**：基于现有 `internal/portfolio`、`portfoliodecision`、`risk` 校验现状，明确资产净值、现金、持仓、成本/估值、敞口、预算、研究时间、来源与版本边界；不可杜撰账户余额。
- [ ] **R7-02 账户/风险预算接入与数据质量**：用户明确输入/导入或可信 Provider 的组合快照、风险政策；验证金额守恒、快照时效、未知数据不当作 0；安全存储与访问控制。
- [ ] **R7-03 组合当前风险画像**：总/单股/行业暴露、现有持仓、集中度和可用风险预算；缺信息时明确 INSUFFICIENT_DATA。

### R7-B：仓位计算和风险裁决

- [ ] **R7-04 确定性 SizingPolicy V1**：固定风险限制 + 依据市场环境调整总仓位上限 + 单笔亏损预算/止损距离 + 现金/集中度约束；研究性建议可复算。
- [ ] **R7-05 多标的组合预算协调**：不同策略/候选共享总预算，不能各自重复使用现金或忽略已有敞口；风险门禁仍可拒绝模型建议。
- [ ] **R7-06 输出与兼容**：独立 `SizingAssessment` 或 `AllocationScenario` 研究对象，含 current/target/delta 与限制原因；不把已有 `PortfolioDecision` 改成订单授权。

### R7-C：策略化管理和验证

- [ ] **R7-07 可替换策略政策**：基础风险预算、固定仓位、三三制、ATR/波动率、分批建仓等作为独立版本化研究政策，优先最小接口而非完整插件框架。
- [ ] **R7-08 策略对照回测**：复用 R6 的历史回放，同一标的/信号、手续费、股票池与时点下比较仓位策略；样本外与不同市场阶段评估，不以最优样本内结果直接上线。
- [ ] **R7-09 组合情景与风险复盘**：What-if、集中度、最大潜在损失、市场恶化时的研究性仓位方案；标记模拟与现实可执行性的差异。

### R7-D：Web/Chat/端到端产品化

- [ ] **R7-10 Portfolio Web 专区**：持仓/预算/策略/限制/情景/历史对照；绝不提供真实订单/自动调仓入口。
- [ ] **R7-11 Conversation Tools**：允许用自然语言读取组合、比较仓位政策、发起 What-if；LLM 不直接提供未计算、未经校验的目标比例。
- [ ] **R7-12 集成与 E2E 验收**：真实完整与账户未知两个端到端路径，覆盖总预算冲突、估值过期、止损/价格缺失、Risk Gate 拒绝、回测一致性。

**R7 Exit Gate**：组合数据可靠；确定性建议、不同政策与历史评估可追溯；Web 和对话共用同一计算结果；未越过研究辅助边界。**之后进入 R8-01**。
