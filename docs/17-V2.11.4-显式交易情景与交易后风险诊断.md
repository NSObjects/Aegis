# V2.11.4 — 组合情景推演与风险影响评估

> **产品定位（长期约束）：Aegis 只负责投资研究、观点形成、风险分析和组合情景推演。系统不会接入券商下单、订单执行、成交回报或交易审批功能。**
>
> V2.11.4 在调用方风险策略与已观察账户估值的基础上，提供显式金额假设下的组合变化测算；不会自行从研究结论推断金额。

## 1. 三份相互独立的输入

- `-portfolio-file`：由调用方明确提供的账户事实；`valuation` 使用精确 CNY 分整数，按 V2.11.2 严格对账，账户 `as_of` 受 V2.11.1 的可选最大年龄限制。
- `-risk-limits-file`：调用方的策略事实，拥有自己的策略 ID、时间点和具体阈值，按 V2.11.3 检验。
- `-trade-scenario-file`：**由调用方自行选择**的一笔金额情景。它仅供研究人员比较不同仓位配置的后果，并非订单或 Agent 自动生成的投资操作。

可选情景 JSON，全部数值仅是**格式示例**，不是行情或仓位建议：

```json
{
  "scenario_id": "manual-what-if-1",
  "as_of": "2026-10-08T15:00:00+08:00",
  "symbol": "600519.SH",
  "side": "BUY",
  "currency": "CNY",
  "notional_fen": 10000
}
```

`notional_fen=10000` 代表假设的 **100 元现金与持仓市值转移**。币种只允许 CNY，金额必须显式给出并为正整数分；支持方向 `BUY`、`SELL`，不支持 `SHORT` 或 `LEVERAGED`。

情景 `as_of` 必须不晚于研究 `requested_as_of`，且不得早于已提供的账户观察时点及风险策略时点；标的必须与研究 symbol 完全相同。未来场景、与研究不符的标的、漏填或空金额均在调用任何模型前拒绝。

## 2. 模拟模型、精度与限制

只在输入清楚、账户金额完全对账且总值大于零时做以下**金额转移的反事实计算**：

| 场景 | 模拟现金变化 | 模拟目标持仓市值变化 |
|---|---|---|
| BUY | `cash - notional` | `position_value + notional` |
| SELL | `cash + notional` | `position_value - notional` |

保持原始 `total_value_fen` 不变：**假定即时按输入金额成交、无手续费、滑点、税费、股价变动或新增/赎回资金**，此为可比较权重的数学情景，不是实际结算结果，也不代表可成交。

- BUY 若金额大于已观察现金，返回 `INSUFFICIENT_CASH`，不输出投影；这不是券商资金可用性保证。
- SELL 若标的没有已观察市值、或金额大于已观察市值，返回 `INSUFFICIENT_POSITION_VALUE`，不输出投影；**没有价格与真实可卖股数，因此不能保证可以完成任何实际卖单**。
- 未观察到估值、`NOT_PROVIDED`、总资产值为零，返回 `INSUFFICIENT_DATA`；不得捏造完整组合。
- 正确计算后逐条检查 `MAX_SINGLE_POSITION_WEIGHT` 与 `MAX_INVESTED_WEIGHT`；超限判定使用整数金额与大整数乘法做**精确比较**，`projected_weight_bps` 仅作向下取整的展示值。
- `WITHIN_MODELED_LIMITS` 仅表示**在这些简化假设下没有超过已提供的两条权重规则**；不保证其他风险、流动性、实际交易价格、卖出份额或法规合规，**不代表 APPROVED**。
- `BREACH` 表示简化情景下明确超出一条或多条限制。

**ScenarioReview 不包含任何执行授权字段。** 研究输出只包含假设、约束、测算结果与不确定性；没有订单接口，也不为将来增加执行接口预留开关。

## 3. 与 Trading Agent 的业务关系

V2.11.4 **不让模型生成场景金额**。完整研究走原路径：

```text
Research → Debate → Research Manager → Trading Agent → Risk Analyst → Portfolio Manager
    ↑                输入和时效在研究前校验                 ↓
用户账户 + 风险策略 + 可选假设金额                 生成 TradeIntent
                                                  ↓
  CANDIDATE → 独立计算假设交易后权重
  MONITOR / REJECTED → NOT_APPLICABLE，不计算任何交易后投影
```

即使 `CANDIDATE` 的情景返回 `WITHIN_MODELED_LIMITS`，也不改变已有 `PortfolioDecision`。后者仍是独立的研究结论，不是交易审批对象。

如果不传 `-trade-scenario-file`，`trade_scenario_review` 从结果中省略，保持原有生产输出契约。新增字段独立于 V2.11.3 的 `current_limits_review`：前者是**假设交易后**，后者是**事实上的当前**限制检查。

## 4. CLI

```bash
go run ./cmd/aegis \
  -symbol 600519.SH \
  -portfolio-review \
  -portfolio-file ./portfolio.json \
  -risk-limits-file ./risk-limits.json \
  -trade-scenario-file ./trade-scenario.json
```

情景文件必须同时存在已启用的 `-portfolio-review` 和 `-risk-limits-file`；不允许悄悄在无策略下假定“无限风险预算”。研究 CLI 默认不生成场景或风险约束。

## 5. 研究情景验收

- 领域单测：买入/卖出、已持仓/新标的、等于和超过限额、显示权重取整、账户状态未知、现金不足、卖出金额超过持仓市值、未来时点和交易标的不匹配。
- 完整 Workflow：错误场景在任何 Agent 前拒绝；非候选不返回投影；候选场景不更改 `PortfolioDecision`；不传场景保持兼容。
- CI 黑盒：调用编译出的 CLI，使用未来场景必须在读取配置/密钥前拒绝。
- Hosted E2E：在新分支真实运行 CLI 的原有 `NOT_PROVIDED` 路径，只检验无场景默认兼容性；不声称有实际券商账户或正式订单。

## 6. 明确排除的产品能力

**不计划实现**：券商下单、订单路由、买卖执行、委托状态、成交回报、账户资金划转、交易审批或订单授权。

价格、成交量约束、滑点、交易费用、T+1 等因素若未来纳入，只用于提升**研究测算的真实性和解释性**，并非建设交易系统的先决条件。

后续功能优先级：情景对比 → 风险驱动因素解释 → 不确定性展示 → 组合研究报告 → 历史验证和回测。
