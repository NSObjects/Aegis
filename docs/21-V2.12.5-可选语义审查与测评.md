# V2.12.5 — 可选语义审查工作流与合成测评

> 目标：允许 Go 调用方主动启用 Semantic Reviewer，在**所有研究、Risk 和 Portfolio 决策完成后**生成独立的语义审查记录。默认关闭，不能授权交易或影响已有决策。

## Go API 启用方式

调用方构造原本的 `research.FullPortfolioWorkflow` 时，可选传入已配置的独立 Reviewer：

```go
workflow := &research.FullPortfolioWorkflow{
    Research: upstream,
    Review: review,
    // 没有此字段时完全不增加模型调用，也不会新增输出 JSON 字段
    SemanticReviewer: &semanticreview.Reviewer{
        Model: independentReviewModel,
        Timeout: 10 * time.Second,
        MaxTasks: 16,
    },
}
result, err := workflow.Run(ctx, input, book)
```

目前只支持**显式 Go 配置**，CLI 不新增默认开关或隐式模型调用。模型由调用方提供，遵循 V2.12.4 已有的严格 JSON 和超时约束。Reviewer 不接收订单权限。

## 输出与失败约定

启用后，主 `FullPortfolioResult` 新增可选的 `semantic_review`：

| Status | 含义 | Report |
|---|---|---|
| `COMPLETED` | 所有任务都有经过身份/结构校验的建议性模型结果 | 非空、但不保证语义真实 |
| `NO_LINKS` | Manager 没有显式 Insight → 论点关联 | 缺省；不会调用模型 |
| `UNAVAILABLE` | 任务构造、模型调用或报告校验失败 | 缺省；不得伪造 Verdict |

`task_count` 是生成的任务数量；失败时 `reason_code` 仅为 `TASK_BUILD_ERROR`、`REVIEWER_ERROR` 或 `INVALID_REPORT`。不会将模型异常或原始输出字符串混入对外 JSON。Review 失败**不改变已完成的 PortfolioReview、风险检查或情景结果**。研究核心阶段本身失败时照常直接返回错误，不得用 Review 掩盖。

`UNCERTAIN` 是模型明确判断存在语义不确定性时的合法 Verdict，**不等于**调用失败。调用失败必须输出 `UNAVAILABLE`，而非伪造任何 Verdict。

## 独立、人工标注的合成测评集

`internal/research/semanticreview/testdata/gold_v1.json` 存放 8 条**虚构研究语句**和人工预期语义分类。样本特意包括：
- 同领域引用却语义相反；
- 同一具体事件却缺乏因果证据；
- 无结构化引用交集但语义相容；
- 缺乏对未来收益确定性判断的依据。

纯函数 `semanticreview.ScoreLabeledReport(tasks, report, labels)` 检查任务/金标准与报告身份、数量和顺序，计算 `exact_matches`、`predicted_uncertain`、`false_consistent_on_contradictory`、`false_contradictory_on_consistent`。不会从领域重合推断标签，也不会对未验证的模型内容计分。

**这些数据只验证计分逻辑和结构化任务处理**：标签不是现实行情，不是模型性能实测结果，更不能宣称真实市场语义审查准确率、召回率或生产可靠性。未运行真实模型测评，未联网读取研究资料，未支付 Provider 调用费用。

## 长期边界

V2.12.5 仍未引入默认工作流的第二模型；仅在 Go 调用方显式启用时才会调用模型。审查报告不得改写 `ResearchPlan`、`TradeIntent`、`RiskContext` 或 `PortfolioDecision`，不构成下单资格。真实质量评估需要独立真实样本、盲标、多标注者一致性、时间一致性/无未来函数、不同模型的误判/成本指标及提示注入测评，另行开发验收。
