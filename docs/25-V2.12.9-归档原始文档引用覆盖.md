# V2.12.9 — Event 原始文档归档引用覆盖校验

> 这是独立可选的**更严格归档入口**，用于检查归档研究中声明的 Event 原始文档 ID，确实存在于同一份内容寻址归档中。不会验证自然语言论点是否由该文档支持，也不会替代真实文档真实性、发布日期或托管方审计。

## API 与输入

`CaptureArchivedResearchDocumentBundle(input)` 复用 V2.12.8 的 `ArchivedResearchInput`，但要求 `EvidenceBytes` 是一个严格 JSON 对象，而不是任意不透明字节：

```json
{
  "documents": [
    {
      "document_id": "canonical-document-id",
      "content": "base64-encoded-raw-document-bytes",
      "sha256": "lowercase-64-character-SHA256-of-decoded-content",
      "evidence_as_of": "2026-09-23T13:00:00+08:00",
      "captured_at": "2026-09-23T14:00:00+08:00"
    }
  ]
}
```

`content` 使用 Go `[]byte` 的标准 JSON Base64 格式；`sha256` 校验解码后的字节，绝不是 Base64 字符串。外层整个 `EvidenceBytes` 的原始 SHA-256 仍需由调用方在本次读取之前独立固化到 `Source.EvidenceSHA256`，原始研究输出独立固化到 `ResearchSHA256`。

原有 `CaptureArchivedResearch` 仍接受此前的不透明 EvidenceBytes。**两个 API 的安全边界不同**；旧 API 的输出不代表已通过逐文档覆盖校验。

## 独立可检查的范围

首先经过原有 Archive Capture 的 ResearchArtifact / Debate / ResearchPlan / EvidenceLedger 和 PIT 完整校验。再检查：

- 严格 JSON 单对象，不接受未知字段、尾随第二个 JSON 值或空文档列表；
- 文档 ID 不为空且没有首尾空白，不能重复；
- 每份文档内容非空，逐字节 SHA-256 与声明值相等；
- 每份文档 `evidence_as_of <= captured_at`，且 `captured_at` 不得晚于 Source.CapturedAt / Source.RequestedAsOf，`evidence_as_of` 不得晚于 Source.EvidenceAsOf；
- 从归档的 EventContext 中，收集 Event.EvidenceDocumentIDs、Fact.EvidenceDocumentIDs、Fact.Groundings.DocumentID，要求每个引用 ID 都出现在归档文档集合中；不支持无 Event 文档引用的严格模式；
- 只输出按文档 ID 稳定排序的 `ArchivedDocumentAudit{document_id,sha256}` 和原有**未标注** Candidate，不返回原始文档内容、Gold、标注人或其他模型结论。

没有被研究引用的归档文档不纳入输出覆盖列表。此校验不验证其文本与引述 `Quote` 的实际对应关系；`Grounding` 内容是否真实、时间是否由独立系统证明、是否存在其他未归档材料，仍需外部审计。

## 数据治理边界

从通过校验的 UNLABELED Candidate 开始，由独立研究审核人再进行真实文档保管/PIT 核实、盲标、分歧仲裁、受控 Holdout 冻结。任何文档哈希成功不等于该文档来自可信新闻或公告源，也不能让合成样本得到质量门禁的 PASS。

本增量没有修改默认在线决策工作流、TradeIntent、Risk、Portfolio、CLI 或真实下单行为；测试仅使用虚构研究与文档字节，没有调用 LLM、行情或外部服务。
