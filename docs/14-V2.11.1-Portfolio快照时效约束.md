# V2.11.1 — Portfolio 快照时效约束

> 目标：阻止已过期的、但 JSON 结构完全合法的账户快照参与当前投资研究的组合风险评审。此功能不接券商、不推断账户金额，也不替代真实账户数据接入。

## 背景

V2.10 已建立独立的 PortfolioContext 与确定性的 PortfolioDecision，并要求账户的 `as_of` 不能晚于研究截止时刻。

但如果用户把一周前的 `POSITIONS` 或 `EMPTY` 快照提交给今天的研究，V2.10 只能验证日期未来自未来，**无法判定它是否过期**。短线研究不应悄悄把旧账户当作当前账户。

## 业务契约

新增 `portfolio.ValidateAt(book, requestedAsOf, maxAge)`：

- 先执行现有 `portfolio.Validate`，保持账户三态和持仓校验不变。
- `requestedAsOf` 是本次研究请求的有效时点，**不是执行校验的机器当前时间**。适用于历史回放；避免同一输入在不同机器运行时出现不同结果。
- 观察到的 `EMPTY` 或 `POSITIONS`：`portfolio.as_of <= requested_as_of`；若指定 `maxAge > 0`，还必须满足 `requested_as_of - portfolio.as_of <= maxAge`。
- `NOT_PROVIDED` 始终表示没有观察到账户，不会被伪造为符合时效的空账户；现有 Risk Analyst 将其判为 `INSUFFICIENT_CONTEXT`。
- `maxAge == 0` 表示未开启新鲜度策略（保留 V2.10 兼容性），负值是配置错误，必须拒绝。
- 过期快照明确返回错误，停止后续 Market / Event / Trading / Risk / Portfolio 工作流；不能在错误情况下继续输出貌似完整的组合判断。

**阈值由调用方决定**，不为 A 股强行假定“昨天有效”或“2 小时就过期”。真实券商接口同步时间、交易日历、现金/资产估值均尚不可用；这一约束不声称验证账户数据来源真实性。

## CLI

现有 `-portfolio-review -portfolio-file` 不变。按需求可额外指定：

```bash
go run ./cmd/aegis \
  -symbol 600519.SH \
  -portfolio-review \
  -portfolio-file ./portfolio.json \
  -portfolio-max-age 24h
```

示例中 `24h` 只是**用户明确指定的配置值**，不是默认的市场策略。

- 未指定：最大年龄检查关闭，原有未来时间保护仍生效。
- 指定负数：拒绝。
- 未启用 `-portfolio-review` 而指定正的 `-portfolio-max-age`：拒绝。
- 账户数据为空：`NOT_PROVIDED` 明确下游风险不充分，绝不据此核准交易。

## 验收

1. `ValidateAt` 对时区、刚好到达阈值、超过阈值、未来账户、未知账户、未启用策略均有确定性测试。
2. `FullPortfolioWorkflow` 在账户过期时所有上游/下游 Agent 调用次数必须为 0，结果必须为空。
3. CLI 在加载任何模型、Runtime 或数据源之前拒绝过期账户及非法 `maxAge`。
4. 现有正常 `-portfolio-review` 的默认行为不改变。不得借该功能引入模拟持仓、自动交易或凭空生成风险预算。

下一阶段才考虑账户数据来源与完整风险预算的独立契约，包括来源标识与可信同步时点、总资产和现金定义、估值口径、以及交易提案的规模。**未具备这些输入时，不应声称可以计算集中度或审批实际下单。**
