# R6 历史回测验收

R6 已具备离线回放、成交模拟、滚动验证和研究反馈。真实历史归档及独立复核仍待提供。测试数据用于验证计算和时点拒绝行为。

## 固定输入和结果

在待验收提交中运行以下命令。输入采用[滚动回测验证格式](WEB_RESEARCH_API.md#滚动回测验证)。

```sh
go build -buildvcs=true -o /tmp/aegis-r6 ./cmd/aegis-pullback-scan
/tmp/aegis-r6 --r6-evidence /path/to/validation.json > r6-evidence.json
```

命令分别读取和验证同一归档两次，核对原始字节指纹和报告是否一致。输出提供 Go 版本、可用的 Git 构建信息、归档及报告 SHA-256，以及每个测试窗口的候选、缺失、平仓与独立标签计数。报告 SHA-256 取 `report` 字段按 Go 紧凑 JSON 序列化后的字节。归档重跑仍须保留原始验证文件。覆盖为零时，输出会保留零计数；收益和分类指标按其数据可用性显示。

## 关闭阶段所需证据

| 核对事项 | 可接受证据 |
| --- | --- |
| 历史目录和股票池 | 归档来源、当时可见的股票池成分及其版本、完整交易日与停牌记录 |
| 行情及复权时点 | 日线和因子的实际可用时间与发布版本，配有可回查的归档引用 |
| 成交输入 | 可追溯的开盘价、涨跌停、开盘可成交量及持仓期间的价格连续性 |
| 独立验证 | 独立审核方在同一提交用相同归档复跑，记录指纹、样本外覆盖和限制 |
| 研究反馈 | 至少一条可回查的样本外结果关联到原研究、后续观察和研究记忆 |

如果只有以当前供应商接口重查的历史数据，须先确认它能提供原发布版本和实际可用时间。TuShare 短期 Canary 或缓存预热可以证明特定查询可用，尚不足以建立历史时点覆盖。工具输出的来源和审核状态固定为待核实，审核结论由独立人员另行记录。

## 没有旧归档时开始采集

在有权限的运行环境中配置 `TUSHARE_TOKEN`。交易日收盘且数据已发布后，显式指定一批最多 20 个主板标的，输出到一个新的文件。

```sh
go run ./cmd/aegis-pullback-scan --capture-pit /path/to/new-snapshot.json --symbols 600519.SH,000001.SZ
go run ./cmd/aegis-pullback-scan --replay-pit /path/to/new-snapshot.json
```

采集使用上海当前日期，写入日历、股票池和行情实际取得的时间。回查到的历史日线及因子也记录为本次取得，无法证明更早何时可用。输出以原子方式创建，同名文件不会被覆盖。归档只覆盖明确选择且当日符合主板股票池的标的，未观察到日线时保留缺失状态。每个交易日保留独立文件。

这些快照用于填充验证文件的 `backtest.signals`。开盘成交深度、涨跌停数据和独立结果标签仍需从各自的当时来源归档；当前采集命令只获取信号计算的数据，不会启动回测或自动下单。
