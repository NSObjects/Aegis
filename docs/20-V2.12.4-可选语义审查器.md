# V2.12.4 — 可选 Eino Semantic Reviewer

> 状态：独立的 Research Team Reviewer 组件。必须由调用方**显式调用**，不会自动接入 `PortfolioReview`、Trading、Risk 或 Portfolio；更不具备券商/下单能力。

## 流程

```text
ResearchArtifact + DebateState + ResearchPlan
  → semanticreview.BuildTasks(...)   // 已验证的真实论点关联
  → (&semanticreview.Reviewer{Model: ..., Timeout: ..., MaxTasks: ...}).Review(ctx, tasks)
  → *semanticreview.Report / error  // 仅供审阅参考
```

Reviewer 复用已有 Eino `model.BaseModel[*schema.AgenticMessage]`，只发起**一次** `Generate`。调用方自行选择模型和配置；本组件不读取密钥、不下载数据、不执行工具。默认 `Timeout=30s`、`MaxTasks=32`；调用方可显式设置正值。模型调用使用 `context.WithTimeout`，故依赖模型适配器遵守上下文取消，不保证强制中止忽略 Context 的第三方实现。

无显式 Insight→论点关联时，`BuildTasks` 返回零任务；`Review` 直接返回空 Finding 的 Report，**不调用模型**，且不意味着已证明研究一致。

## 模型输入和输出限制

输入 JSON 仅包含经验证的任务、原始论点文本与引用。用户/来源文字是**不可信数据**，不是 Reviewer 的新指令。模型的引用重合标签（同事件、同领域、无共同引用）也不能当作语义一致性真值。

输出必须是唯一一个 JSON 对象，固定 `Report` Schema：`symbol` 和按任务原顺序排列的 `findings[]`，每条含 `insight_index`、`argument_id`、`verdict`、`rationale`，不确定时另含 `limitations`。

- 允许 Verdict：`CONSISTENT`、`CONTRADICTORY`、`UNCERTAIN`。
- 严格拒绝未知 JSON 字段、额外 JSON 值、Markdown 代码围栏、空响应、非 Assistant / 非单一文本区块、超大输出（256KiB）、错误 ID、漏项与重排。
- `ValidateReport` 校验**标的、身份、数量、顺序、枚举和说明**，**不验证模型判断在自然语言或事实层面的正确性**。
- 超时、取消、提供方异常、非法 JSON 或验证失败返回 `(nil,error)`；**绝不根据引用一致性伪造 CONSISTENT，也不会用伪造的 UNCERTAIN 把服务异常掩盖成模型判断。**
- Reviewer 必须由调用方主动调用，不修改 Manager Plan、TradeIntent、RiskContext 或 PortfolioDecision。生产主流程在本次提交后应保持完全相同。

## 验证边界

普通 CI 通过 Eino 假模型进行确定性测试：模型输入、零任务、任务上限、超时/取消、Provider 失败、模型非文本、多余 JSON、不确定性说明。**这不是 Hosted E2E**，不代表真实大模型的语义正确率、稳健性、服务费用或抗提示注入能力已得到证实。

今后如将 Reviewer 以显式开关接入生产工作流，必须另行设计预算/超时、调用失败的 UI 状态、人工复核、基准样本与误判评估。禁止将报告用于自动下单或直接覆盖研究决策。
